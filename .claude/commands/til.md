# TIL 정리

`CLAUDE.md`의 규칙(요약 금지, 틀린 내용 교정, `til: v2` 표시, 기사 시험 연계)을 **전부 따른다.** 이 파일은 그 규칙을 실행하는 절차다.

정리에는 두 가지 방식이 있다. 상황에 맞는 쪽을 쓴다.

| 방식 | 언제 | 입력 |
|---|---|---|
| **A. 대화 기반 정리** (기본) | 사용자가 튜터(Claude)와 대화하며 수강했고 "정리해줘"라고 할 때 | 강의 원문(링크·파일) + 이 대화에서 나온 질문·답·혼잣말 |
| **B. 붙여넣기 재구성** | 사용자가 정리본(Gemini 등)을 TIL 파일에 붙여넣어 둔 경우 | `TIL/`의 기존 파일 |

`$ARGUMENTS`가 파일 경로면 방식 B로 그 파일을, 아니면 방식 A로 진행한다.

---

## 방식 A. 대화 기반 정리

### 1. 재료 모으기

- **강의 원문**: 대화 중에 읽은 레슨 텍스트(링크는 Claude in Chrome으로 열어 읽은 것). 레슨이 여러 개면 전부 포함한다.
- **대화 내용**: 사용자의 질문, 혼잣말과 그에 대한 확인·교정, Claude가 보탠 설명.
- 이미 읽은 레슨은 다시 열지 않아도 된다. 다시 열 필요가 있으면(내용이 불확실할 때) 열어서 확인한다.

### 2. 내용 분류

모든 내용을 아래 네 종류로 **출처에 따라** 나눈다. 섞으면 시험 범위를 알 수 없다.

| 종류 | 출처 | 표기 |
|---|---|---|
| 본문 | 강의 원문(강사가 실제로 말한 것) | 일반 본문 |
| 바로잡은 것 | 사용자가 잘못 이해했다가 교정된 것 | `> ♻️ 처음엔 ~로 알았으나, ~가 맞다.` |
| 보충 | 수업에 없지만 대화 중 보탠 것 | `> ➕ **더 알아두기**` 블록 |
| 시험 대비 | 정보처리기사·정보보안기사와 겹치는 것 | `> 📝 **기사 시험 포인트** (시험명)` 블록 |

- 대화 중 Claude가 한 말이 불확실했거나 나중에 정정됐다면 **정정된 내용만** 쓴다.
- 확신 없는 내용은 쓰지 말고 사용자에게 묻는다.
- `📝` 블록은 시험 범위·출제 여부가 확실할 때만 쓴다. 빈도를 단정하지 않는다.

### 3. 파일 만들기

- 경로: `TIL/YYYY-MM-DD_주제.md` (날짜는 오늘. 파일명에 `:` `?` `*` 등 Windows 금지 문자를 쓰지 않는다. 같은 날 파일이 이미 있으면 이어 쓸지 사용자에게 묻는다.)
- 구조:

```markdown
---
tags: [영어소문자, 하이픈-사용, 3개에서5개]
til: v2 YYYY-MM-DD
---

# {파일명 그대로}
> 작성일: YYYY-MM-DD

## 🔗 관련 글

- [이전 글 제목](이전파일경로.md) — 어떤 점이 이어지는지 한 줄

## ❓ 아직 모르겠는 것

- (사용자가 직접 막힌 것, 확정이 필요한 것)

## 주제 1: ...

### 소주제

(강의 원문 내용을 줄이지 않고 다듬어서)

## 정리

(핵심만 모은 요약. 본문을 대체하지 않는다)

## ✅ 확인 질문

1. ...
```

- `🔗 관련 글`: `TIL/`의 이전 파일을 살펴 같은 주제를 찾는다. 없으면 섹션째 생략한다. 표준 마크다운 링크를 쓴다.
- `❓ 아직 모르겠는 것`: **사용자가 실제로 막혔다고 한 것**을 쓴다. Claude가 추측해서 채우지 않는다. 확실하지 않으면 사용자에게 무엇을 쓸지 묻거나 비워 둔다(`- `).
- 레슨의 표·예시는 빠짐없이 옮긴다. 이 파일은 시험공부용이다.
- 이 대화에서 사용자가 파고든 부분(왜?에 답한 설명)은 `➕` 블록에 충분히 담는다.

### 4. 확인 질문 규칙

- **주제 하나당 2개꼴.** 주제가 많은 날 일부가 통째로 빠지지 않게, 만들기 전에 주제 수를 세고 배분한다.
- **답은 쓰지 않는다.** 질문만.
- 단순 암기보다 설명을 요구하는 질문을 우선한다.
- 제목은 정확히 `## ✅ 확인 질문`. 복습 노트가 이 제목으로 끌어온다.

## 방식 B. 붙여넣기 재구성

사용자가 Gemini 정리본을 시간 순서대로 붙여넣은 TIL 파일을 **주제 중심으로 재배치**한다.

### 대상 파일

`$ARGUMENTS`가 있으면 그 파일. 없으면 `TIL/` 안에서 오늘 날짜로 시작하는 파일. 없으면 가장 최근 수정 파일을 대상으로 하되 **작업 전에 사용자에게 확인**한다.

### 이미 정리된 파일인지 확인

파일을 열어서 판단하지 않는다. 아래 한 줄이면 된다.

```bash
grep -L "til: v2" TIL/*.md
```

출력된 파일이 **아직 정리되지 않은 것**이다. `## ✅ 확인 질문`이 있다는 것만으로 완료로 판단하면 안 된다. 구버전(v1)으로 정리된 파일도 그것을 가지고 있다.
대상 파일에 이미 `til: v2`가 있으면 다시 정리할지 사용자에게 묻는다.

### 절대 원칙

**요약하지 않는다. 재배치하고 다듬는다.** 정리 후 본문 분량이 **원본의 80% 미만**이면 되돌리고 다시 한다. (정정으로 줄어든 분량은 계산에서 제외하고, 보고 때 밝힌다.)

- 서술형으로 통일(`~함` → `~한다`), 오타 수정, 비문 정리. **줄이는 게 아니라 고쳐 쓰는 것이다.**
- 강사의 말은 `강사에 따르면 ~`처럼 출처가 드러나게 쓴다.
- 사용자의 감상·혼잣말은 내용을 살려 인용 블록으로 옮긴다. 지우지 않는다.
- 틀린 내용은 `♻️`, 보강은 `➕`, 시험 연계는 `📝` 블록으로 분리한다 (방식 A의 분류 표와 같다).

### 순서

1. **읽기**: 파일 전체를 읽는다. 길어도 앞부분만 보고 판단하지 않는다.
2. **주제 파악**: 시간대(`09:00-10:00`)를 무시하고 실제 주제를 파악한다. 같은 주제가 여러 시간대에 흩어져 있는 것을 하나로 합치는 것이 이 방식의 존재 이유다.
3. **표시 처리**: Gemini 표시가 있으면 우선 근거로 삼는다. 묶은 뒤 이 표시 줄은 본문에서 제거하고, 키워드는 frontmatter `tags`로 옮긴다.

| 표시 | 처리 |
|---|---|
| `📍 정리 #3` | 조각 순서 번호 |
| `🏷️ 키워드: http, dns` | 같은 키워드의 조각끼리 묶는다 |
| `🔗 이어짐: 정리 #2` | 그 조각과 한 주제로 합친다 |
| `♻️ 정정: ...` | 지목된 틀린 설명을 **지우고 올바른 내용으로 교체**한다 (이것이 삭제의 유일한 예외). 교체한 자리에 `♻️ 처음엔 ~` 한 줄을 남긴다 |

4. **재구성**: 방식 A의 파일 구조를 따른다. 학습과 무관한 내용(출석 안내, 팀 편성, 초대 링크)은 맨 아래 `## 🗂 수업 외 기록`으로 모은다. 삭제하지 않는다.
5. **확인 질문**: 방식 A의 규칙과 같다.

## 공통 마무리

### 복습 노트 갱신

저장소 루트의 `복습_확인질문.md`를 연다. **최신 날짜가 위로** 오도록 `# 📅 날짜별 확인 질문` 아래에 추가한다. 이미 그 날짜 항목이 있으면 갱신한다.

```markdown
## 2026-10-02 — 데이터베이스 기초·PK/FK·1:N·M:N

![[TIL/2026-10-02_파일명#✅ 확인 질문]]
```

- 제목 줄의 주제는 그날 tags를 한글로 풀어 적는다.
- 임베드는 위키링크(`![[ ]]`)를 쓴다. 확장자(`.md`)는 붙이지 않는다.

### 보고

작업 후 사용자에게 알린다.

- 글자 수. **반드시 파이썬으로 센다.** `wc -m`은 환경에 따라 바이트를 세서 한글이 3배로 부풀려진다.

```bash
python -c "import sys;t=open(sys.argv[1],encoding='utf-8').read();print(len(t))" 파일경로
```

- (방식 B) 원본 / 정리 후 글자 수, 합쳐진 주제, 수업 외 기록으로 옮긴 항목
- 연결한 이전 글
- `❓ 아직 모르겠는 것`에 무엇을 넣었고 그 근거가 무엇인지

### 커밋

**커밋하지 않는다.** 이 컴퓨터는 자동 커밋이 없으므로, 파일을 고친 뒤 **"커밋·푸시가 필요하다"고 알린다.** 사용자가 요청하면 그때 한다.

### 주의

- 이미지 링크(`![](../attachments/...)`)는 경로를 건드리지 않는다.
- 코드블록 **안의 내용은 절대 수정하지 않는다.** 열었으면 반드시 닫는다.
- 파일당 `#`은 맨 위 제목 하나뿐이다. 문서 안 주제는 `##`, 소주제는 `###`.
