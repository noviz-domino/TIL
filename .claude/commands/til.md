# TIL 정리

수업 중 Gemini 대화를 시간 순서대로 붙여넣은 TIL 파일을, 주제 중심으로 재배치한다.

## 대상 파일

`$ARGUMENTS` 가 주어지면 그 파일. 없으면 `TIL/` 안에서 **오늘 날짜(YYYY-MM-DD)로 시작하는 파일**.
오늘 날짜 파일이 없으면 `TIL/` 에서 가장 최근에 수정된 파일을 대상으로 하되, **작업 전에 사용자에게 확인**한다.

## 절대 원칙

**요약하지 않는다. 재배치하고 다듬는다.**

- 설명을 짧게 줄이지 않는다. 내용을 삭제하지 않는다.
- "덜 중요해 보이는 것"을 임의로 쳐내지 않는다.
- 정리 후 본문 분량이 **원본의 80% 미만**이면 뭔가 잘못한 것이다. 되돌리고 다시 한다.

중복 병합은 예외다. 같은 내용이 두 번 설명된 경우 더 자세한 쪽을 남기고 합친다.
이때도 한쪽에만 있는 정보는 반드시 살린다.

### 문장 다듬기 (분량 축소가 아니다)

이 노트의 목적은 기록 보존이 아니라 **시험공부에 쓸 수 있는 정리본**이다.

- 서술형으로 통일: `~함` `~하는것` `~라고함` `~인듯` → `~한다` `~하는 것이다`
- 명백한 오타·오기 수정 (대채→대체, 횝사이트→웹사이트, 잠조→참조 등)
- 비문·중복 표현을 정리해 읽히는 문장으로 재작성
- 강사의 말을 옮긴 대목은 `강사에 따르면 ~` 처럼 출처가 드러나게 쓴다
- 사용자의 감상·혼잣말(`#솔직히 난 ~하고싶은데..?`)은 **내용을 살려서** 인용 블록으로 옮긴다. 지우지 않는다.

### 틀린 내용 교정과 내용 보강

**틀린 내용**은 올바르게 고치고 그 자리에 흔적을 남긴다:

```markdown
> ♻️ 처음엔 (틀린 이해)로 알았으나, (맞는 내용)이 맞다.
```

**보강할 내용**은 본문에 섞지 않고 반드시 별도 블록으로 분리한다:

```markdown
> ➕ **더 알아두기**
> (수업에서 안 나왔지만 알아두면 좋은 내용)
```

강사가 말한 것과 Claude가 보탠 것이 구분되어야 시험 범위를 알 수 있다.
확신 없는 내용은 쓰지 말고 사용자에게 묻는다.

## 작업 순서

### 1. 읽기

대상 파일 전체를 읽는다. 길어도 전부 읽는다. 앞부분만 보고 판단하지 않는다.

### 2. 주제 파악

시간대(`09:00-10:00` 등)로 나뉜 조각들을 무시하고, **실제로 무슨 주제를 다뤘는지** 파악한다.
같은 주제가 여러 시간대에 흩어져 있는 경우가 많다. 그게 이 명령의 존재 이유다.

Gemini 정리본에 다음 표시가 있으면 그것을 우선 근거로 삼는다
(`제미나이_시작_프롬프트.md` 를 쓰고 있으면 붙어 있다).

| 표시 | 처리 |
|---|---|
| `> 📍 정리 #3` | 조각의 순서 번호. `🔗 이어짐` 이 가리키는 대상을 찾는 데 쓴다 |
| `> 🏷️ 키워드: http, dns` | 같은 키워드를 가진 조각끼리 묶는다 |
| `> 🔗 이어짐: 정리 #2 API 기초` | 그 조각과 한 주제로 합친다 |
| `> ♻️ 정정: 정리 #1의 XX는 틀렸고 YY가 맞음` | 아래 **정정 처리** 규칙대로 |

표시가 여러 줄로 나뉘어 있을 수도, 한 줄에 합쳐져 있을 수도 있다. 둘 다 처리한다.

```markdown
> 📍 정리 #1
> 🏷️ 키워드: n8n, telegram

> 📍 정리 #1 🏷️ 키워드: n8n, telegram        ← 이것도 같은 의미
```

사용자는 정리를 수시로 요청하므로 조각이 짧고 많다. 조각 하나가 한 주제인 경우는 드물다.
**여러 조각을 이어 붙여 하나의 주제를 완성하는 것이 이 명령의 주된 작업이다.**

표시가 없는 옛날 파일이면 내용을 읽고 직접 판단한다.
묶은 뒤 이 표시 줄들은 본문에서 제거한다. 키워드는 frontmatter `tags` 로 옮긴다.

### 정정 처리 — 유일한 삭제 예외

`♻️ 정정` 표시가 있으면 **지목된 틀린 설명을 지우고 올바른 내용으로 교체한다.**
틀린 정보가 문서에 남아 있으면 시험공부 때 해롭기 때문이다. 이것이 "삭제하지 않는다" 규칙의 유일한 예외다.

단, 교체한 자리에 다음 한 줄을 남긴다. 무엇을 착각했는지가 복습에 가장 쓸모 있는 정보다.

```markdown
> ♻️ 처음엔 (틀린 이해)로 알았으나, (맞는 내용)이 맞다.
```

정정 때문에 줄어든 분량은 80% 기준 계산에서 제외한다. 보고할 때 몇 자가 정정으로 줄었는지 밝힌다.

### 3. 재구성

다음 구조로 다시 쓴다.

```markdown
---
tags: [영어소문자, 하이픈-사용, 3개에서5개]
---

# {원래 파일명 그대로}
> 작성일: YYYY-MM-DD

## 🔗 관련 글

- [이전 글 제목](이전파일경로.md) — 어떤 점이 이어지는지 한 줄

## {주제 1}

### {소주제}

{원문 내용 그대로}

## {주제 2}

...

## ✅ 확인 질문

1. {질문}
2. {질문}
3. {질문}
4. {질문}
5. {질문}

---

## 🗂 수업 외 기록

{출석 안내, 팀 회의, 초대 링크 등 학습과 무관한 내용}
```

### 4. 각 항목 규칙

**제목 레벨**
- 파일 맨 위 `#` 은 하나만. 문서 안 주제는 `##`, 소주제는 `###`.
- 원문에 `#` 이 여러 개면 전부 `##` 으로 내린다.

**tags**
- 영어 소문자, 공백 대신 하이픈. 예: `[http, dns, rest-api]`
- 3~5개. 그날의 핵심 주제만.

**🔗 관련 글**
- `TIL/` 의 다른 파일들을 살펴, 같은 주제를 다룬 이전 글을 찾는다.
- 표준 마크다운 링크를 쓴다: `[제목](2026-07-22_....md)` — GitHub에서도 동작해야 한다.
- 연결할 글이 없으면 이 섹션을 통째로 생략한다. 억지로 만들지 않는다.

**✅ 확인 질문**
- **주제 하나당 2개꼴**로 만든다. 주제가 3개면 6개, 6개면 12개 정도.
  개수를 미리 정해두면 주제가 많은 날 일부가 통째로 빠진다.
- 특정 주제에 질문이 하나도 없으면 안 된다. 만들기 전에 주제 목록을 세고 배분한다.
- **답은 쓰지 않는다.** 질문만.
- 단순 암기("HTTP의 약자는?")보다 설명을 요구하는 질문("Stateless인데 로그인이 유지되는 이유는?")을 우선한다.
- 제목은 정확히 `## ✅ 확인 질문` 으로 한다. 복습 노트에서 이 제목으로 끌어오기 때문이다.

**🗂 수업 외 기록**
- 출석/휴강 안내, 팀 편성, 디스코드 링크 등을 여기로 모은다.
- **삭제하지 않는다.** 나중에 필요할 수 있다. 학습 내용과 섞이지만 않으면 된다.
- 해당 내용이 없으면 섹션을 생략한다.

### 5. 복습 노트 갱신

저장소 루트의 `복습_확인질문.md` 를 연다. 없으면 만든다.

해당 날짜 항목이 없으면 **최신 날짜가 위로 오도록** 추가한다. 이미 있으면 갱신한다.

```markdown
## 2026-07-30 — HTTP, DNS, Stateless

![[2026-07-30_서버_클라이언트_설명#✅ 확인 질문]]
```

- 제목 줄의 주제는 그날 tags를 한글로 풀어 적는다.
- 임베드는 위키링크(`![[ ]]`)를 쓴다. 옵시디언에서 질문이 그 자리에 펼쳐져 보이게 하기 위함이다.
- 파일명에 확장자(`.md`)는 붙이지 않는다.

### 6. 보고

작업 후 사용자에게 다음을 알린다.

- 원본 / 정리 후 글자 수 (분량이 유지됐는지 확인용)
- 합쳐진 주제 (예: "웹 기초"가 3곳에 흩어져 있어 하나로 합침)
- 연결한 이전 글
- 수업 외 기록으로 옮긴 항목

커밋은 하지 않는다. Obsidian Git이 알아서 하거나, 사용자가 확인 후 결정한다.

## 이미 정리된 파일인지 판별하는 법

별도의 기록 파일은 두지 않는다. 파일 자체를 보고 판단한다.

**아래 두 가지가 모두 있으면 이미 정리된 파일이다.**

1. 맨 위 frontmatter에 `tags:` 가 있다
2. `## ✅ 확인 질문` 섹션이 있다

이미 정리된 파일이 대상으로 지정되면 **작업 전에 사용자에게 다시 정리할지 묻는다.**
붙여넣기가 추가돼서 다시 정리해야 하는 경우가 있으므로 거부하지는 않는다.

아직 정리 안 된 파일 목록이 필요하면 이렇게 뽑는다.

```bash
grep -L "확인 질문" TIL/*.md
```

## 주의
- 이미지 링크(`![](../attachments/...)`)는 경로를 건드리지 않는다.
- 코드 블록 안의 내용은 절대 수정하지 않는다.
