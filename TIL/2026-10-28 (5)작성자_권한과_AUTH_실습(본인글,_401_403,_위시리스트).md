## 주제 1: 작성자는 요청값이 아니라 인증 결과에서 결정한다

mysite_auth에 게시글을 추가하고 로그인한 사용자를 작성자로 저장한다. 요청은 제목·내용만 받는다. 사용자에게 user_id를 마음대로 선택하게 하지 않고 검증된 current_user.id로 작성자를 정한다. 수정·삭제에는 본인 여부를 검사한다.

| 메서드·경로 | 역할 | 인증·권한 | 정상 코드 |
|---|---|---|---|
| POST /posts-auth | 게시글 생성 | 로그인 필요 | 201 |
| GET /posts-auth | 전체 목록 | 불필요 | 200 |
| GET /posts-auth/{post_id} | 상세 | 불필요 | 200 |
| PUT /posts-auth/{post_id} | 수정 | 작성자 본인 | 200 |
| DELETE /posts-auth/{post_id} | 삭제 | 작성자 본인 | 204 |
| GET /me/posts | 내가 쓴 글 | 로그인 필요 | 200 |
| GET /users/{user_id}/posts | 특정 사용자 글 | 불필요 | 200 |

```python
# mysite_auth/models/post.py
from typing import TYPE_CHECKING

from sqlalchemy import ForeignKey, String, Text
from sqlalchemy.orm import Mapped, mapped_column, relationship

from database import Base

if TYPE_CHECKING:
    from mysite_auth.models.user import User


class PostAuth(Base):
    __tablename__ = "post_auth"

    id: Mapped[int] = mapped_column(primary_key=True, autoincrement=True)
    title: Mapped[str] = mapped_column(String(50), nullable=False)
    content: Mapped[str] = mapped_column(Text, nullable=False)
    user_id: Mapped[int] = mapped_column(ForeignKey("user_auth.id"), nullable=False)

    user: Mapped["User"] = relationship(back_populates="posts")
```

user_id는 DB 외래키, user는 관계 속성이다. 사용자 모델에는 앞 파트의 id·email·hashed_password·created_at에 추가로 `posts: Mapped[list["PostAuth"]] = relationship(back_populates="user")`를 정의한다. 양쪽 파일의 TYPE_CHECKING import는 타입 검사에 사용하고 실제 모델 등록은 models/__init__.py에서 PostAuth와 User를 import해 수행한다.

```python
# mysite_auth/models/__init__.py
from .post import PostAuth
from .user import User
```

```python
# mysite_auth/schemas/post.py
from pydantic import BaseModel, ConfigDict, Field

from mysite_auth.schemas.user import UserResponse


class PostCreate(BaseModel):
    title: str = Field(min_length=1, max_length=50)
    content: str = Field(min_length=1)


class PostListResponse(BaseModel):
    id: int
    title: str
    user: UserResponse

    model_config = ConfigDict(from_attributes=True)


class PostDetailResponse(BaseModel):
    id: int
    title: str
    content: str
    user: UserResponse

    model_config = ConfigDict(from_attributes=True)
```

응답의 user는 비밀번호·해시가 빠진 UserResponse이다. 목록과 상세 둘 다 작성자 DTO를 중첩하지만 목록에는 본문이 없다.

## 주제 2: Repository와 Service의 역할·조회 옵션

Repository는 Session으로 저장·조회·속성 수정·삭제를 하고 commit 경계는 Service가 관리한다. 작성자를 중첩 응답에 사용하므로 joinedload(PostAuth.user)로 준비한다. 목록 응답 생성 시 작성자마다 추가 조회하지 않도록 앞의 N+1 개념을 적용한 것이다.

```python
# mysite_auth/repositories/post_repository.py
from sqlalchemy import select
from sqlalchemy.orm import Session, joinedload

from mysite_auth.models.post import PostAuth
from mysite_auth.schemas.post import PostCreate


class PostRepository:
    def save(self, db: Session, new_post: PostAuth):
        db.add(new_post)
        return new_post

    def find_all(self, db: Session):
        return db.scalars(
            select(PostAuth).options(joinedload(PostAuth.user)).order_by(PostAuth.id)
        ).all()

    def find_by_id(self, db: Session, post_id: int):
        return db.scalar(
            select(PostAuth)
            .options(joinedload(PostAuth.user))
            .where(PostAuth.id == post_id)
        )

    def find_by_user_id(self, db: Session, user_id: int):
        return db.scalars(
            select(PostAuth)
            .options(joinedload(PostAuth.user))
            .where(PostAuth.user_id == user_id)
            .order_by(PostAuth.id)
        ).all()

    def update(self, db: Session, post: PostAuth, data: PostCreate):
        post.title = data.title
        post.content = data.content
        return post

    def delete(self, db: Session, post: PostAuth):
        db.delete(post)


post_repository = PostRepository()
```

```python
# mysite_auth/services/post_service.py
from fastapi import HTTPException, status
from sqlalchemy.orm import Session

from mysite_auth.models.post import PostAuth
from mysite_auth.repositories.post_repository import post_repository
from mysite_auth.schemas.post import PostCreate
from mysite_auth.schemas.user import UserResponse


class PostService:
    def create_post(self, db: Session, data: PostCreate, current_user: UserResponse):
        with db.begin():
            new_post = PostAuth(
                title=data.title, content=data.content, user_id=current_user.id
            )
            post_repository.save(db, new_post)
        return new_post

    def get_posts(self, db: Session):
        return post_repository.find_all(db)

    def get_post(self, db: Session, post_id: int):
        post = post_repository.find_by_id(db, post_id)
        if post is None:
            raise HTTPException(
                status_code=status.HTTP_404_NOT_FOUND,
                detail="게시글을 찾을 수 없습니다.",
            )
        return post

    def get_posts_by_user_id(self, db: Session, user_id: int):
        return post_repository.find_by_user_id(db, user_id)

    def update_post(
        self, db: Session, post_id: int, data: PostCreate, current_user: UserResponse
    ):
        with db.begin():
            post = self.get_post(db, post_id)
            if post.user_id != current_user.id:
                raise HTTPException(
                    status_code=status.HTTP_403_FORBIDDEN,
                    detail="본인의 게시글만 수정할 수 있습니다.",
                )
            updated_post = post_repository.update(db, post, data)
        return updated_post

    def delete_post(self, db: Session, post_id: int, current_user: UserResponse):
        with db.begin():
            post = self.get_post(db, post_id)
            if post.user_id != current_user.id:
                raise HTTPException(
                    status_code=status.HTTP_403_FORBIDDEN,
                    detail="본인의 게시글만 삭제할 수 있습니다.",
                )
            post_repository.delete(db, post)


post_service = PostService()
```

작성자 본인 검사 전에는 대상 게시글 존재를 확인한다. 없는 글은 404이고, 인증된 사용자지만 작성자가 다르면 403이다. 예외가 begin 블록을 벗어나면 해당 변경 트랜잭션은 취소된다. 조회도 트랜잭션을 시작할 수 있으므로 수정·삭제 대상 조회를 begin 안에 둔다.

## 주제 3: Router의 두 의존성과 인증·인가 구분

| 구분 | 검사 | 위치 | 실패 |
|---|---|---|---|
| 인증 | 유효한 토큰과 실제 사용자인가 | Depends(get_current_user) | 401 |
| 인가 | 현재 사용자가 이 글의 작성자인가 | Service의 사용자 ID 비교 | 403 |

게시글 Router는 prefix=/posts-auth, tags=mysite_auth이다. DB Session과 인증 사용자 DTO는 서로 다른 매개변수로 받는다.

```python
@router.post("", response_model=PostDetailResponse, status_code=status.HTTP_201_CREATED)
def create_post(
    data: PostCreate,
    db: Annotated[Session, Depends(get_db)],
    current_user: Annotated[UserResponse, Depends(get_current_user)],
):
    return post_service.create_post(db, data, current_user)


@router.get("", response_model=list[PostListResponse])
def get_posts(db: Annotated[Session, Depends(get_db)]):
    return post_service.get_posts(db)


@router.get("/{post_id}", response_model=PostDetailResponse)
def get_post(post_id: int, db: Annotated[Session, Depends(get_db)]):
    return post_service.get_post(db, post_id)


@router.put("/{post_id}", response_model=PostDetailResponse)
def update_post(
    post_id: int,
    data: PostCreate,
    db: Annotated[Session, Depends(get_db)],
    current_user: Annotated[UserResponse, Depends(get_current_user)],
):
    return post_service.update_post(db, post_id, data, current_user)


@router.delete("/{post_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_post(
    post_id: int,
    db: Annotated[Session, Depends(get_db)],
    current_user: Annotated[UserResponse, Depends(get_current_user)],
):
    post_service.delete_post(db, post_id, current_user)
```

사용자 Router는 /me에서 인증 DTO를 그대로 반환한다. /me/posts는 본문·URL의 임의 사용자 ID가 아니라 인증 결과의 ID를 사용하고, 공개 /users/{user_id}/posts는 경로 번호로 해당 사용자의 글을 조회한다.

```python
@router.get("/me", response_model=UserResponse)
def get_me(current_user: Annotated[UserResponse, Depends(get_current_user)]):
    return current_user


@router.get("/me/posts", response_model=list[PostListResponse])
def get_my_posts(
    db: Annotated[Session, Depends(get_db)],
    current_user: Annotated[UserResponse, Depends(get_current_user)],
):
    return post_service.get_posts_by_user_id(db, current_user.id)


@router.get("/users/{user_id}/posts", response_model=list[PostListResponse])
def get_posts_by_user(user_id: int, db: Annotated[Session, Depends(get_db)]):
    return post_service.get_posts_by_user_id(db, user_id)
```

```python
# main.py의 인증 관련 import와 라우터 등록

from mysite_auth.routers.post_router import router as auth_post_router

app.include_router(auth_router)
app.include_router(auth_post_router)
app.include_router(user_router)
```

강의 확인 절차는 로그인·Authorize 후 제목 ‘작성자가 있는 게시글’, 내용 ‘로그인한 사용자가 작성자로 저장됩니다.’로 생성하여 응답 user.id를 확인하는 것이다. /me/posts에는 본인 글만 보이고, 다른 계정의 수정·삭제는 403, 토큰 없는 쓰기 요청은 401이어야 한다. 이 문서 작성에서 실제 두 계정이나 토큰을 만들지는 않았다.

> 📝 **기사 시험 포인트** (정보보안기사)
> 인증만 통과했다고 자원 소유권을 검증한 것은 아니다. 요청자가 보내는 user_id 대신 검증된 주체의 식별자를 사용하고 대상 자원 소유자와 비교해야 접근 통제가 성립한다. 댓글의 게시글 소속 검사와 로그인 사용자의 권한 검사는 서로 다른 조건이다.

## 주제 4: AUTH 실습의 사용자·위시리스트 요구사항

이 과제는 기존 상품 관리 API에 회원가입·로그인·개인 위시리스트를 추가하는 요구사항이다. 구현 코드를 읽었다는 의미가 아니라 과제 명세를 읽은 것이며 현재 게시판의 태그 API를 위시리스트 API로 부르지 않는다.

### 사용자 모델과 인증 API

| users 컬럼 | 조건 |
|---|---|
| id | 자동 생성 정수 기본키 |
| email | 유효한 이메일, 최대 254자, 필수·고유, 소문자로 저장·조회 |
| hashed_password | 필수, Argon2id로 해싱한 비밀번호 |
| created_at | DB가 생성하는 가입 시각 |

가입 비밀번호는 15~128자이고 로그인은 1~128자이다. 응답에 비밀번호·해시를 포함하지 않는다. JWT는 문자열 사용자 ID sub와 iat·exp를 담고 Bearer 헤더로 전송한다.

| API | 입력·응답 | 정상 코드 |
|---|---|---|
| POST /auth/signup | email·password → id·email·created_at | 201 |
| POST /auth/login | email·password → access_token·token_type bearer | 200 |
| GET /me | 본문 없음 → 인증 사용자의 id·email·created_at | 200 |

중복 이메일은 409, 미가입·잘못된 암호는 401, 입력 조건 위반은 422이다. /me는 토큰 없음·검증 실패·사용자 없음에서 모두 401이다.

### 위시리스트 모델과 소유권

| wishlist_items 컬럼 | 조건 |
|---|---|
| id | 항목 자동 생성 정수 기본키 |
| user_id | users.id를 참조하는 필수 외래키 |
| product_id | products.id를 참조하는 필수 외래키 |

user_id·product_id 조합을 고유하게 하되 다른 사용자끼리 같은 상품을 담는 것은 허용한다. user_id는 입력 본문이 아니라 인증 결과로 지정한다. 이는 앞의 게시글·태그 연결 테이블과 같은 M:N 원리를 사용자·상품으로 바꾼 것이다.

| API | 입력 | 반환·정상 코드 |
|---|---|---|
| POST /me/wishlist | 양의 정수 product_id | 항목 id·user_id·product_id, 201 |
| GET /me/wishlist | 없음 | 본인 항목 목록, 항목별 id·product, 200 |
| DELETE /me/wishlist/{wishlist_item_id} | 없음 | 본인 연결 항목만 삭제, 본문 없이 204 |

목록의 product에는 id·name·final_price·category가 들어간다. 전 API는 인증이 필요하다. 토큰 문제·사용자 없음은 401, 다른 사용자의 항목 삭제는 403, 없는 상품·항목은 404, 본인 목록의 동일 상품 재등록은 400, product_id 조건 위반은 422이다. 항목이 없으면 빈 목록이다.

위시리스트 연결만 삭제할 때 상품 자체와 다른 사용자의 항목은 유지한다. 상품을 삭제할 때는 그 상품에 연결된 위시리스트 항목을 함께 삭제한다. ‘연결 해제’와 ‘공유 자원 삭제’의 방향을 구분해 구현해야 한다.

## 정리

인증 주체는 신뢰 가능한 검증 결과에서 얻고, 대상 자원 소유권은 Service에서 검사한다. 작성자 관계와 nested DTO에는 앞의 외래키·relationship·즉시 로딩을 활용한다. 상품 위시리스트 과제도 관계와 소유권·중복 제약을 결합한 확장이다.
