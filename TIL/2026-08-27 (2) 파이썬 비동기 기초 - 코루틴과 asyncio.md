## 1. 비동기란?

- **동기(sync)**: 한 작업이 끝날 때까지 기다렸다가 다음 작업 시작. (카페에서 커피 나올 때까지 카운터 앞에 서서 기다리기)
- **비동기(async)**: 기다리는 동안 다른 작업 진행. (진동벨 받고 자리에 앉아 다른 일 하기)

| 방식 | 작업이 기다릴 때 | 예시 흐름 |
|---|---|---|
| 동기 | 프로그램도 함께 기다림 | A 시작 → A 완료 → B 시작 → B 완료 |
| 비동기 | 다른 작업을 진행함 | A 요청 → 기다리는 동안 B 요청 → 완료된 것부터 처리 |

**언제 쓰나**: 계산이 오래 걸리는 게 아니라 **결과를 기다리는 시간(I/O 대기)이 긴 작업**. 네트워크 API 요청, DB 조회, 파일 읽기/쓰기 등.

> 웹 브라우저에서 `fetch()`나 JS의 `async`/`await`, `Promise`와 원리가 동일함. 파이썬은 `asyncio`로 같은 발상을 구현.

## 2. 이벤트 루프

```
작업 A 요청 → A가 응답을 기다림 → 그동안 작업 B 진행 → A의 응답이 오면 A를 이어서 실행
```

이벤트 루프가 "기다리는 작업"과 "실행 가능한 작업"을 감시하다가, `await` 지점에서 다른 작업으로 스위칭.

⚠️ **함정**: 이벤트 루프에 작업이 **여러 개 등록되어 있어야** 스위칭이 일어남. 하나씩 `await`하면 결국 순차 실행.

## 3. 코루틴(coroutine)과 `async`/`await`

### 이름의 유래

**co(함께) + routine(루틴)** = "협력하는 루틴들".

일반 함수(subroutine)는 호출되면 끝까지 실행되고 끝. 코루틴은 **중간에 멈췄다가(suspend) 나중에 그 지점부터 다시 이어서(resume)** 실행 가능. 서로 실행을 양보하며 협력적으로 돌아가서 코루틴.

### 기본 코드

```python
import asyncio

async def async_work(name: str, seconds: int) -> str:
    print(name, "시작")
    await asyncio.sleep(seconds)
    print(name, "완료")
    return f"{name} 결과"
```

- `async def`로 정의한 함수 = **코루틴 함수**
- 호출하면 바로 실행되는 게 아니라 **코루틴 객체**(= 실행 예정 주문서)가 생김
- `await`를 붙여야 실제로 실행되고 결과를 받음
- `time.sleep()` ❌ / `asyncio.sleep()` ✅ — `time.sleep()`은 CPU를 통째로 멈춰서 이벤트 루프가 다른 작업으로 못 넘어감. `asyncio.sleep()`은 "기다리는 동안 양보"함

### `await`를 쓸 수 있는 위치 규칙

**판단 기준은 "그 줄이 적혀 있는 함수가 `async def`인가"** — 호출 대상이 코루틴인지는 무관.

```python
def main():                            # 일반 함수
    result = await async_work("A", 1)  # ❌ SyntaxError (async_work가 코루틴이어도 소용없음)

async def main():                      # 코루틴 함수
    result = await async_work("A", 1)  # ✅ OK
```

`for`, `if`, `while`, `with`는 **함수 스코프를 만들지 않음**. 그래서 `for`문 안의 `await`도 그걸 감싸는 바깥 함수가 `async def`이기만 하면 됨.

> 예외: Jupyter/Colab은 이미 이벤트 루프가 돌고 있어서 셀에 top-level `await`를 바로 쓸 수 있음.

## 4. 흔한 함정 — `async`만 쓰면 자동으로 동시 실행되지 않는다

```python
for name in ["작업 A", "작업 B", "작업 C"]:
    result = await async_work(name, 1)   # 하나씩 순서대로 await
```

→ 1초짜리 작업 3개인데 **총 3초**. A가 완전히 끝나야 B가 시작되기 때문.

`main` 함수 자체는 코루틴이든 아니든 **위에서 아래로 순차 실행**됨. 안의 모든 `await`가 끝나야 리턴함.

## 5. `asyncio.gather()`로 진짜 동시에 실행하기

```python
async_results = await asyncio.gather(
    async_work("작업 A", 1),
    async_work("작업 B", 1),
    async_work("작업 C", 1),
)
```

→ **총 약 1초**. 세 작업이 번갈아 진행됨.

### gather의 정체

- `asyncio.gather`는 `async def`가 아닌 **일반 함수**. 호출하면 결과가 아니라 대기 객체(Future)를 반환
- 그래서 `await asyncio.gather(...)`로 써야 실제 실행됨
- 인자는 반드시 코루틴/Task/Future 같은 **awaitable**이어야 함 (`time.sleep()` 같은 동기 함수는 못 넣음)
- `await`를 쓰므로 자연히 **`async def` 안(또는 노트북 top-level)에서만** 호출 가능

### 동작 3단계

1. **등록** — 넘겨받은 코루틴들을 하나씩이 아니라 **전부 동시에** 이벤트 루프에 Task로 등록
2. **동시 실행** — A가 `sleep`으로 멈추면 즉시 B로, B도 멈추면 C로 인터리빙
3. **결과 취합** — 끝난 순서가 아니라 **넘겨준 순서 그대로** 리스트 반환

### 비유

- `for` + `await` = "A 주문 → 받을 때까지 서서 기다림 → 그제서야 B 주문"
- `gather()` = "A, B, C 동시에 주문 넣고 진동벨 3개 쥐고 대기 → 되는 대로 처리 → 마지막에 A→B→C 순서로 정리"

### 동시성 ≠ 병렬성

파이썬 인터프리터는 싱글 스레드(GIL). 물리적으로 동시 실행되는 게 아니라, `await`로 멈추는 틈에 다른 코루틴을 조금씩 실행하는 **인터리빙(concurrency)**임.

## 6. `.py` 파일에서 실행하기 — `asyncio.run()`

```python
if __name__ == "__main__":
    asyncio.run(main())
```

### 왜 필요한가 — 닭과 달걀 문제

1. `await`는 `async def` 안에서만 쓸 수 있다
2. 코루틴은 `await`를 붙여야 실행된다

→ 그럼 **맨 바깥의 `main()`은 누가 실행하나?** 이 무한 고리를 끊는 것이 `asyncio.run()`.

### 수영장 비유

- **수영장 안** = 비동기 세계. 헤엄(`await`) 가능
- **수영장 밖(땅 위)** = 일반 파이썬 코드. 헤엄 불가
- 프로그램은 항상 **땅 위에서 시작**하므로 물속으로 들어가는 **입구**가 필요
- `asyncio.run(main())` = "수영장(이벤트 루프)을 만들고, `main()` 코루틴을 던져 넣어 실행하고, 끝나면 정리해줘"

### 세부 사항

- `asyncio.run()`의 인자는 **반드시 코루틴 객체**여야 함. 일반 함수를 넣으면 `TypeError`

  ```python
  def main(): ...
  asyncio.run(main())        # ❌ TypeError

  async def main(): ...
  asyncio.run(main())        # ✅
  ```

- `main()`이라는 이름은 관례일 뿐. 코루틴 함수면 뭐든 가능: `asyncio.run(async_work("A", 1))`
- 프로그램 전체에서 `asyncio.run()`은 보통 **딱 한 번, 맨 마지막에만** 등장 (입구는 하나면 충분)
- **Jupyter에서는 쓰면 안 됨** — 이미 이벤트 루프가 돌고 있어서 충돌 발생

### `if __name__ == "__main__":` 이란?

- 파일을 **직접 실행**하면 (`python script.py`) → `__name__`은 `"__main__"`
- 다른 파일에서 **import**되면 → `__name__`은 파일 이름(`"script"`)

즉 "이 파일이 직접 실행됐을 때만 아래를 실행해라"는 뜻. 이게 없으면 import만 해도 `main()`이 자동 실행돼버림. 비동기와 무관한 파이썬의 표준 관례.

## 7. 실제 API 요청에 적용 (httpx)

`httpx`는 `requests`와 사용법이 비슷하면서 **비동기 요청을 지원**하는 HTTP 클라이언트. `pip install httpx`

```python
import httpx

async def get_post(client: httpx.AsyncClient, post_id: int) -> dict:
    url = f"https://jsonplaceholder.typicode.com/posts/{post_id}"
    response = await client.get(url)
    response.raise_for_status()
    return response.json()

# 순차 요청
async with httpx.AsyncClient(timeout=10.0) as http_client:
    for post_id in post_ids:
        post = await get_post(http_client, post_id)   # 하나씩 → 느림

# 동시 요청
async with httpx.AsyncClient(timeout=10.0) as http_client:
    concurrent_posts = await asyncio.gather(
        *(get_post(http_client, post_id) for post_id in post_ids)
    )   # 한꺼번에 → 빠름
```

`*(...)`는 제너레이터를 언패킹해서 `gather()`에 여러 인자로 펼쳐 넣는 문법.

## 핵심 한 줄 정리

- `async def` = 중간에 멈췄다 이어갈 수 있는 코루틴 함수
- `await` = 그 줄이 적힌 함수가 `async def`일 때만 사용 가능
- `gather()` = 여러 코루틴을 한꺼번에 이벤트 루프에 등록해 진짜 동시성 확보
- `asyncio.run()` = 동기 세계에서 비동기 세계로 들어가는 유일한 출입구
