### AI 에이전트 (AI Agent)

- **개념**: 단순 질문 답변을 넘어, 스스로 목표를 달성하기 위해 판단하고 외부 도구(검색, 코드 실행, API 등)를 사용해 작업을 수행하는 AI 시스템.
    
      
    
- **AI 에이전트 엔지니어의 역할**: 에이전트의 흐름(Workflow)을 설계하고, LLM과 외부 데이터베이스 및 도구를 연결하며, 의도대로 동작하도록 정밀하게 제어하는 백엔드/AI 개발자.
    
      
    
- **핵심 요소**: LLM 성능 자체보다 **상태 관리(State Management)** 및 **외부 도구 활용(Tool Calling)** 설계가 중요함.
    
      
    

### 프롬프트 기법 (Prompting Techniques)

- **제로샷 (Zero-shot)**: 모델에게 예시를 주지 않고 바로 질문하는 기법.
    
      
    
- **퓨샷 (Few-shot)**: 몇 가지 입출력 예시를 프롬프트에 미리 보여주어 답변 형식이나 패턴을 유도하는 기법.
    
      
    - **원샷 (One-shot)**: 예시를 1개만 제공하는 방식.
        
          
        
    - **실무 활용**: LLM의 출력을 특정 형식(예: JSON)으로 고정하거나 복잡한 분류 작업을 지시할 때 필수적으로 사용함.
        
          
        
    - **LangChain 연동**: `FewShotPromptTemplate` 클래스를 통해 퓨샷 예시를 동적으로 관리하고 삽입 가능.
        
          
        

### 프롬프트 체이닝 (Prompt Chaining)

- **개념**: 하나의 복잡한 작업을 여러 개의 작은 프롬프트 단계로 쪼개고, 앞 단계의 출력 결과를 다음 단계의 입력으로 연결하는 기법.
    
      
    
- **목적**: 한 번의 요청으로 인한 환각(Hallucination) 현상이나 지시사항 누락을 방지하고 정확도를 높임.
    
      
    
- **실무 활용**: 긴 보고서 작성, 코드 생성 및 검증, 복잡한 데이터 추출 프로세스 자동화 등에 사용.
    
      
    
- **LangChain과의 관계**: LangChain이라는 이름 자체가 이러한 프롬프트 체이닝을 코드 단에서 쉽게 구현해 준다는 의미에서 유래함.
    
      
    

### 루브릭 (Rubric)

- **개념**: AI의 답변이나 수행 결과를 정량적으로 평가하고 검증하기 위해 세운 명확한 평가 기준표.
    
      
    
- **실무 활용**: LLM의 출력을 자동 평가(LLM-as-a-Judge)하거나, 에이전트의 결과물이 사용자에게 전달되기 전 가이드라인(Guardrails)을 통과했는지 검증할 때 기준이 됨.
    
      
    
- **관련 도구**: LangChain/LangGraph 생태계에서는 **Ragas**, **LangSmith** 등의 모니터링/평가 도구와 함께 사용함.
    
      
    

### LangChain과 관련 패키지

- **LangChain 개념**: LLM 기반 애플리케이션을 빠르게 개발할 수 있도록 프롬프트 관리, RAG(외부 데이터 연결), 메모리, API 연동 등을 표준 인터페이스로 제공하는 프레임워크.
    
      
    
- **주요 구성 요소**: Prompts, Models, Indexes/VectorStores, Chains.
    
      
    
- **LangGraph와의 차이점**:
    
      
    - **LangChain**: 일직선 형태의 단순 체인(Chain) 및 프롬프트 체이닝 구현에 적합.
        
          
        
    - **LangGraph**: 조건 분기(If-Else) 및 순환 제어(Loop)가 필요한 복잡한 에이전트의 흐름을 그래프 구조로 제어.
        
          
        

#### 주요 설치 패키지 역할

Bash

```
pip install google-genai langchain langchain-google-genai langchain-community
```

- `google-genai`: 구글 Gemini 모델을 다루기 위한 최신 공식 SDK.
    
      
    
- `langchain`: 프롬프트, 체인, 에이전트 등 LangChain의 핵심 표준 기능이 담긴 본체.
    
      
    
- `langchain-google-genai`: LangChain 내에서 구글 Gemini 모델을 편리하게 연동하는 전용 패키지.
    
      
    
- `langchain-community`: 써드파티 도구, 다양한 데이터베이스, 커뮤니티 제작 연결 모듈이 모여있는 확장팩 라이브러리.
    
      
    

### ⚠️ 헷갈리기 쉬운 점

- **패키지 파편화 구조**: 과거에는 `langchain` 라이브러 하나에 모든 기능이 들어있었으나, 라이브러리가 무거워짐에 따라 현재는 Core 본체와 각 LLM/도구별 연동 패키지(`langchain-google-genai`, `langchain-community` 등)로 분리되어 관리됨.
    
      
    
- **구글 SDK 버전 차이**: 기존 `google-generativeai`에서 최신 `google-genai` 표준 패키지로 세대교체가 진행 중이므로 패키지명을 정확히 구분하여 설치해야 함.

## Gemini API Interactions API와 LangChain 활용

> 📍 정리 #2
> 🏷️ 키워드: gemini, invoke, prompttemplate, lcel, parser
> 🔗 이어짐: 정리 #1 AI 에이전트 및 LangChain 기초

### Gemini Interactions API vs LangChain

* **Gemini Interactions API**: 구글이 서버 단에서 대화 맥락(State) 관리 및 백그라운드 작업을 직접 처리해 주는 엔지니어링 엔드포인트 (`interaction_id`로 대화 기억).
* **차이점 및 역할**:
* **Interactions API**: Gemini 모델을 스마트하게 호출하는 '엔진(부품)' 역할.
* **LangChain**: 여러 LLM, Vector DB, 외부 API 및 비즈니스 로직을 연결하는 시스템 전체 '프레임워크(뼈대)' 역할.


* **관계**: 상충되는 개념이 아니라, `langchain-google-genai` 패키지 내부에서 Gemini의 Interactions API를 활용하는 구조.

---

### 실행 명령 `.invoke()` 및 메서드 표준화

* **개념**: 파이썬/프레임워크 전반에서 함수나 객체를 호출/실행하는 대표적인 메서드 명칭.
* **LangChain에서의 역할**: 프롬프트, 모델, 체인 등 모든 표준 객체(LCEL)에 통일된 실행 명령어로 제공됨.
* **주요 인터페이스 세트**:
* `.invoke()`: 단일 입력값에 대해 실행.
* `.batch()`: 여러 입력값을 한 번에 처리.
* `.stream()`: 실시간 스트리밍 답변 반환.
* `.ainvoke()`: 비동기(Async) 환경에서의 실행.



---

### PromptTemplate과 값 주입

* **사용 이유**: 파이썬 `f-string` 대신 LangChain 전용 객체로 관리하여 변수 검증, 퓨샷 결합, 체인 연동을 안전하게 수행함.
* **주요 메서드/속성**:
* `PromptTemplate.from_template()`: 문자열(중괄호 `{변수}` 포함)을 받아 프롬프트 템플릿 객체 생성.
* `invoke({...})`: 템플릿 내 중괄호 변수명과 일치하는 Key-Value 딕셔너리를 받아서 최종 프롬프트 객체(`StringPromptValue`)로 완성.
* `text` / `to_string()`: 완성된 프롬프트 객체에서 LLM에 전달할 순수 텍스트 문자열만 추출.



#### 변수 작성 및 대화형 템플릿 (`ChatPromptTemplate`)

* **변수명 설정**: 중괄호 안의 이름(예: `{role}`, `{question}`)은 정해진 키워드가 아니라 **개발자가 임의로 지정하는 변수명**임. 단, `invoke()`로 전달하는 딕셔너리의 Key 이름과 완전히 일치해야 함.
* **`ChatPromptTemplate`**: 단순 단일 텍스트가 아닌, 대화 역할이 구별된 챗봇 구조를 생성함.
* `SystemMessage` ("system"): AI의 페르소나, 규칙, 지침 등 가장 우선시되는 절대적 배경 지시문.
* `HumanMessage` ("human"): 사용자의 질문/입력.
* `AIMessage` ("ai"): 이전 대화 답변.



---

### 출력 파서 (Output Parser)

* **개념**: AI 모델이 출력한 자연어 텍스트(String)를 파이썬 객체, JSON, 리스트 등 코드에서 즉시 사용할 수 있는 데이터 구조로 변환/정제하는 도구.
* **주요 종류**:
* `StrOutputParser`: 단순 텍스트 추출 및 불필요한 메타데이터 제거.
* `JsonOutputParser` / `PydanticOutputParser`: JSON 및 구조화된 데이터 형태로 변환.



---

### LCEL (LangChain Expression Language) 파이프라인

* **개념**: 파이프(`|`) 연산자를 사용하여 여러 구성 요소를 하나의 체인(파이프라인)으로 직관적으로 연결하는 표현식.

```python
# 개발자가 선언한 변수들을 파이프(|) 연산자로 연결
chain = prompt | model | parser

# 체인 단일 실행
result = chain.invoke({"question": "파이썬이 뭐야?"})

```

* **구분자 (`|`)**: 앞 객체의 출력값(Output)을 뒤 객체의 입력값(Input)으로 자동 전달하는 LangChain 표준 연산자 (`__or__` 구현).
* **순서와 데이터 흐름**: 반드시 지정된 순서만 고정된 것은 아니나, **앞 단계의 출력 타입과 뒤 단계의 입력 타입이 서로 호환**되어야 함. (예: `Prompt`의 출력 ➡️ `Model`의 입력 ➡️ `Parser`의 입력)

---

### ⚠️ 헷갈리기 쉬운 점

* **변수명과 Key 일치**: 프롬프트 템플릿 안의 `{변수}` 이름과 `invoke({"변수": "값"})`의 키 이름이 다르면 `KeyError`가 발생함. (role, question 등은 정해진 키가 아니라 자유 지정 변수임)
* **`|` 파이프라인의 데이터 타입 미스매치**: `chain = model | prompt`처럼 데이터 흐름(Input/Output Schema)이 맞지 않는 순서로 연결하면 `TypeError` 또는 `ValueError`가 발생함.
* **중괄호 텍스트 표현**: 템플릿 내에서 변수가 아닌 일반 중괄호 문자를 출력하고 싶을 때는 `{{`, `}}`처럼 두 번 겹쳐서 작성해야 함.
