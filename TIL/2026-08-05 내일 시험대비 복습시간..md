## AI 모델 기초 및 LLM의 한계와 대응 전략

> 📍 정리 #1
> 
> 🏷️ 키워드: input, llm, token, context, rag

### AI 모델의 제어 요소와 LLM의 본질

- **AI 모델 제어 제약**: 사용자가 직접 제어 가능한 핵심 요소는 Input(프롬프트)이다. 개발자 관점에서는 파라미터(Temperature, Top-p 등)나 파인튜닝 데이터를 통해 출력을 추가 제어한다.
    
- **LLM의 본질**: LLM은 문장을 '이해'하는 시스템이 아니라, 입력된 토큰을 바탕으로 **"다음에 올 가장 확률 높은 토큰"을 계속 예측해서 이어 붙이는 확률 모델**이다.
    

### LLM의 주요 한계점

1. **환각 (Hallucination)**
    
    - 확률상 '그럴듯한 토큰'을 생성하기 때문에 완전한 거짓말을 당당하게 만들어내는 현상이다.
        
2. **지식 컷오프 (Knowledge Cutoff)**
    
    - 특정 시점까지의 데이터로만 사전 학습(Pre-training)되었기 때문에, 학습 이후 발생한 최신 정보나 실시간 사건은 알지 못한다.
        
3. **컨텍스트 윈도우의 한계**
    
    - 대화 맥락(Context)을 수용하는 용량에 한계가 있어 완벽한 무한 기억력을 갖지 못한다.
        

### 컨텍스트 초과 시 대응 전략

대화 용량이 다 찼을 때 선택할 수 있는 두 가지 핵심 방식:

1. **컴팩트 (Compact / 압축)**
    
    - 이전 대화 내용을 요약해 용량을 줄인다. 다만 디테일이나 소스코드 조건 등의 정보가 유실될 위험이 있다.
        
2. **새로운 세션 시작 (Session Reset)**
    
    - 대화를 리셋하고 새로운 세션을 시작하되, 작업 기록을 보존해 전달한다.
        
    - **실무 활용법**:
        
        - 기획서/설계서를 미리 `.md` 파일로 작성해 보관한다.
            
        - 진행 상황을 `TODO.md` 등의 파일로 지속해서 기록한다.
            
        - Git Commit을 통해 작업 단위를 자주 저장하여, 컨텍스트가 꼬이거나 AI 출력이 오작동할 때 즉시 복구(Rollback)할 수 있도록 한다.
            

### ⚠️ 헷갈리기 쉬운 점

- **LLM의 단기 기억(Memory)**: LLM 내부에는 인간이나 컴퓨터의 RAM과 같은 물리적 '단기 기억 장치'가 독립적으로 존재하는 것이 아니다. 대화가 이어질 때마다 이전 대화 내역 전체(Context)를 매번 Input으로 다시 전달하여 다음 토큰을 예측하는 방식으로 작동한다.





## LLM 토큰 비용 구조와 세션 관리

> 
> 🔗 이어짐: 정리 #1 AI 모델 기초 및 LLM의 한계와 대응 전략

### 토큰 청구 방식과 비용 구조

- **합산 청구**: API 비용 계산 시 Input 토큰과 Output 토큰 요금이 합산되어 청구된다.
    
- **단가 차이**: Input 토큰보다 **Output 토큰의 단가가 훨씬 비싸다.** (Output 생성 시 토큰을 하나씩 순차 계산하는 자원 소모가 크기 때문)
    

### 대화 누적(Input 토큰)으로 인한 두 가지 주요 문제점

1. **비용 문제 (토큰 누적)**
    
    - 대화가 길어질수록 이전 대화 기록 전체가 매 요청마다 Input 토큰으로 재전송된다.
        
    - 이에 따라 한 번 질문할 때마다 소모되는 Input 토큰 양이 기하급수적으로 증가하여 비용이 폭증한다.
        
2. **품질 문제 (노이즈 발생 및 답변 저하)**
    
    - 불필요하거나 쓸데없는 대화 내용이 Input에 누적되면 노이즈로 작용한다.
        
    - AI의 집중력을 떨어뜨려 원하지 않는 답변이나 잘못된 결과를 유발한다.
        

### 대응 전략: 새 세션 활용

- 대화 내용이 길어지거나, 쓸데없는 내용이 쌓였거나, 작업 주제가 바뀔 때는 **새 세션(New Session)을 만드는 것**이 비용 절감과 답변 품질 유지 면에서 모두 유리하다.
