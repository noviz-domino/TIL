## 2. 정적 웹사이트와 서버-클라이언트 구조

> 11:00–12:00 정적 웹사이트와 동적 웹사이트의 기본 설명

### 2.1 서버-클라이언트 구조의 설명

지금 만든 게임은 완성된 게임을 그대로 배포한 것이라, **정적 웹사이트**로 제공된 것이다.

HTML에 소리는 mp3로, 디자인은 CSS 등으로 이미 모든 것이 세팅되어 있다.

그래서 여러 사람이 플레이하며 결과를 공유하거나 경쟁하는 실시간 온라인 시스템은 만들 수 없다.

과거에 CD로 프로그램을 배포하던 것과 다를 것이 없다.

그래서 사용하는 것이 **서버-클라이언트 구조**다.

> ➕ **더 알아두기**
> 정적(static)과 동적(dynamic)의 차이는 **"누가 접속해도 똑같은 파일이 오느냐"**다.
> - **정적** — 서버는 미리 만들어둔 파일을 그대로 건네준다. 누가 언제 접속해도 같은 내용이다. (내 게임, GitHub Pages)
> - **동적** — 요청을 받을 때마다 서버가 계산해서 **그 사람에게 맞는 결과**를 새로 만들어 보낸다. (로그인, 내 점수 순위, 장바구니)
>
> 랭킹 기능을 붙이려면 왜 서버가 필요한지가 여기서 설명된다. 점수를 **다른 사람도 볼 수 있는 한 곳**에 저장해야 하는데, 정적 웹사이트에는 그 저장할 곳이 없다.

### 2.2 서버를 만들 때는 DB가 필요하다

서버를 사용한다는 것은 데이터를 받아서 가공해 제공하는 것이 기본이기 때문에, 데이터베이스가 반드시 필요하다.

### 2.3 개발자의 종류

클라이언트를 개발하는 개발자를 **프론트엔드**,

서버를 개발하는 개발자를 **백엔드** 개발자로 통칭한다.

AI 엔지니어는 굳이 따지자면 백엔드 쪽에 더 가깝다.

그래서 데이터베이스를 반드시 알고 있어야 한다.

파이썬을 배울 것이므로 FastAPI를 배우면 좋을 것 같다고 한다.

> ➕ **더 알아두기**
> **FastAPI**는 파이썬으로 서버(API)를 만드는 프레임워크다. AI 분야에서 특히 많이 쓰이는 이유는, AI 모델을 다루는 라이브러리가 대부분 파이썬으로 되어 있어서 **모델과 서버를 같은 언어로 붙일 수 있기** 때문이다.
> 이름 그대로 빠르기도 하지만, 실제로 편한 점은 코드를 짜면 **API 문서와 테스트 화면이 자동으로 생성**된다는 것이다(`/docs` 주소로 접속). 어제 배운 n8n의 HTTP Request 노드가 호출하던 그 API를, 이번에는 내가 직접 만드는 쪽이 되는 셈이다.

## 3. API와 기본 CS

> 13:00–14:00 기본적인 컴퓨터과학(CS) 내용 설명, API란

### 3.1 주로 JSON을 사용하게 될 것

파이썬을 주로 쓰기도 하고, 대부분의 데이터 전송에 JSON을 쓰는 것이 추세이기 때문이다.

### 3.2 API란?

다른 회사가 만들어놓은 기능을 밖에서 쓸 수 있도록 만들어놓은 것을 API라고 한다.

정확히는 **기능 자체가 아니라, 그 기능을 사용할 수 있도록 지원하는 창구**가 API다.

예) "저희는 이런 형태의 데이터를 이렇게 처리해서 드릴게요~" 하는 약속이 API다.

> ➕ **더 알아두기**
> API는 **Application Programming Interface**의 약자다. 여기서 핵심 단어는 **인터페이스**, 즉 '접점'이다.
> "기능 자체가 아니라 기능을 쓰게 해주는 것"이라는 강사의 설명이 정확히 이 뜻이다. 식당으로 치면 **주방(기능)이 아니라 메뉴판과 주문 창구(인터페이스)**가 API다. 주방이 어떻게 요리하는지 몰라도 메뉴판만 보고 주문할 수 있다는 것이 핵심이다.
> 그래서 API를 쓸 때 알아야 할 것은 딱 세 가지다. **어디로 보낼지(URL) / 무엇을 보낼지(요청 형식) / 무엇이 돌아올지(응답 형식)**.

### 3.3 AI 모델보다는 돈 되는 시스템을 구상해라

AI 모델을 만들면 좋겠지만 그럴 자원이 없기 때문에 직접 만드는 것은 불가능하다.

이미 만들어진 AI 모델을 제타처럼 그냥 활용해서, 돈 벌 방법을 구상하는 것이 맞다.

그래서 대부분의 기업이 랭체인이나 n8n처럼 AI를 슬쩍 끼워 넣어 몸집을 불리려고 한다.

실제로는 AI 모델을 보유하지 않고 빌려서, 유통회사처럼 그냥 파는 것이 진실이지만 말이다.

### 4.1 재미나이 API 사용하기

  https://ai.google.dev/gemini-api/docs/get-started?hl=ko#python

바탕화면에 포트폴리오 폴더를 만들어서 이제부터 관리하기 시작할 것이다.

클로드에게 "깃허브에 포트폴리오라는 퍼블릭 레포지토리를 만들어서 폴더와 연결해줘"라고 요청했다.

포트폴리오 레포지토리를 만들었으면, 그 문서 하나에 각각의 프로젝트가 연결되거나 보이도록 구성해야 한다. HR 담당자들은 귀찮아서라도 프로젝트를 하나씩 열어보지 않기 때문에, 한 화면에서 다 보이게 만들어야 한다.

> ➕ **더 알아두기**
> 여기서 말하는 "문서 하나"는 레포지토리 최상단의 **README.md**다. GitHub는 폴더에 들어가면 README.md를 자동으로 펼쳐서 보여주기 때문에, 이 파일이 사실상 표지 역할을 한다.
> 프로젝트마다 **한 줄 설명 + 스크린샷(또는 GIF) + 데모 링크 + 레포 링크**를 표로 정리해두면, 담당자가 클릭 없이 훑을 수 있다. 스크린샷이 특히 중요한데, 코드를 읽지 않아도 무엇을 만들었는지 3초 만에 전달되기 때문이다.

### 4.2 git 레포지토리에서 .gitignore 사용법

이 기능을 사용하면, 올리고 싶지 않은 파일 이름을 이 파일에 적어두었을 때 업로드가 되지 않는다.

그래서 중요한 API 키 같은 것을 보관할 때 사용하게 되어 있다.

> ♻️ 처음엔 ".gitignore에 파일을 올려두면 업로드가 안 된다"로 이해했으나, 정확히는 **.gitignore 안에 파일 이름(또는 패턴)을 적어두면 Git이 그 파일을 추적하지 않는다**는 뜻이다. 파일을 그 안에 넣는 게 아니라, 이름을 목록으로 적는 것이다.

> ➕ **더 알아두기**
> API 키를 다룰 때 실무에서 쓰는 방식은 이렇다.
> 1. 키를 코드에 직접 쓰지 않고 **`.env` 파일**에 적는다. (`GEMINI_API_KEY=xxxx`)
> 2. `.gitignore`에 `.env` 한 줄을 적어서 이 파일이 깃허브에 안 올라가게 막는다.
> 3. 코드에서는 파일 대신 환경변수로 읽는다. (파이썬: `os.environ["GEMINI_API_KEY"]`)
>
> **주의할 함정**: `.gitignore`는 **아직 커밋되지 않은 파일**에만 효과가 있다. 이미 한 번 커밋해서 올라간 키는 나중에 `.gitignore`에 추가해도 **커밋 기록에 그대로 남는다.** 이 경우 파일을 지우는 것으로는 부족하고, **그 키를 즉시 폐기하고 새로 발급받아야** 한다.
