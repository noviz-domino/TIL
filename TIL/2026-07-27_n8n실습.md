## 2. 프롬프트 엔지니어링

> 10:00–11:00 프롬프트엔지니어링의 개념

### 2.1 지금도 배워야 하는 이유

지금은 이제 프롬프트엔지니어링은 안써도 진행해온 개발법이기때문에 랭체인과
랭그래프를 학습하기 위해서는 배워야함. 
랭체인과 랭그래프는 ai에 구조를 덧씌우는것.

### 2.2 프롬프트 엔지니어링의 기초

좋은 프롬프트의 4요소
역할, 맥락, 작업, 형식

역할: 너는 누구야~ (안하면 일반인 수준의 밋밋한 답변을 보여줌)
맥락: 이건 신입 교육룡 자료야. 대상은 비전공자 5명대상이야.(대상,수준이 맞아야됨.)
작업: 아래 약관에서 불리한 고객 조항 3개를 찾아줘(어떤일을 해야하는가)
형식: 표로 만들어서 각항목이 2줄씩, 근거조항번호 표시해서 만들어줘(안하면 매번 다른내용표시.후처리불가)

### 2.3 프롬프트 기법

zero-shot: 예시없이 지시만 시키는것
few-shot : 예시를 몇개 주고 기준을 보여주는것.

Tree-of-Thought :: 갈래를 펼쳐서 탐색하기 ( 서로 다른 접근 3가지를 제안하고, 각각의 장단점을 평가한 뒤, 최선안을 골라 상세화해.)

시스템프롬프트는 규칙을 적는것. 사용자프롬프트는 데이터를 적는것임.

## 3. 노코드 자동화 툴과 n8n

> 13:00–14:00 n6n , make 등의 노코드 자동화 툴 설명, 클로드 코드 결제 설명.

### 3.1 노코드 툴이란

디자인쪽은 미리캠버스, 캔바같은 느낌
n8n은 코드없이 자동화를 할수있게 만들기 위한 느낌.
둘다 전공자나 전문지식이 없어도 할 수 있음.

### 3.2 바이브코딩 vs n8n

다만 클로드로 하는 바이브코딩은 블랙박스라서 안에 로직을 한번에 확인하거나 문제를 찾기 힘들지만 
n8n은 자동화시스템을 구축할수있지만 그럼에도 코드를 수정할수있는 기능을 제공함.

### 3.3 무료(셀프호스팅) vs 유료(n8n cloud)

또한 유료이기도하고 무료이기도 한데 로컬로 자기컴퓨터에 깔아서 실행하겠다고 한다면 무료로 쓸수있음. 다만 24시간 계속 켜둘수 없기때문에 문제가있고
설정과 서버 유지보수등이 필요함. 

유료버전의 경우는 설치도하기 힘든 환경이고 365일 돌아가는 자동화가 필요하다면 유료버전 n8n cloud를 유료결제하여 쓰는것.

셀프호스팅: 내가 직접 서버구축하여 사용, 유지보수 등등 알아서..

n8n 2주 무료 체험버전 가입. 7월 27일가입후 2주동안 사용가능.

로그인하고 왼쪽 메뉴바에서 퍼스널 눌럿서 들어오면됨.

## 4. n8n 실습 — 구글 폼 설문 응답 자동화

> 14:00–15:00 n8n실습
> 15:00–18:00 실습 과제 day02 — 구글폼을 이용한 스프래드시트용 메일 자동화 만들기.

기본 노드 생성과 g메일 스프레드 시트 갱신시 전송해보기.

n8n 기본 사용법 익히기.

노드생성과 구글폼을 이용한 스프래드시트용 메일 자동화 만들기.

### 4.1 🚀 전체 프로세스 개요

3개의 개별 구글 폼(1번: 회원 정보, 2번: 취미/음식, 3번: 영화) 응답을 **구글 시트(통합 시트) 하나로 수집 및 업데이트**하고, 조건에 따라 안내 메일을 발송하는 자동화 워크플로우.

```text
[폼 1/2/3 트리거]
       ↓
[Skip empty rows] (빈 행 제거 / 예외 처리)
       ↓
[Append or Update row] (통합 시트 업데이트)
       ↓
[Get row(s) in sheet] ➔ [If 노드] ➔ [Gmail 발송]
```

### 4.2 🛠️ 핵심 구현 및 노드별 설정

**① 트리거 예외 처리 (Skip empty rows 노드)**

  * 목적: 구글 시트에서 발생할 수 있는 데이터 없는 빈 행(Blank Row)을 미리 걸러냄.
  * 설정 (Filter 노드):
    * Left Value: {{ $json['이메일 주소'] }}
    * Condition: is not empty
  * 필요성: 구글 시트에 빈 줄이 수집되면 매칭 기준값(이메일 주소)이 비어 있어 후속 노드에서 The 'Column to Match On' parameter is required 에러가 발생함.
**② 통합 시트 데이터 업데이트 (Append or Update Row)**

  * 1번 폼 (최초 제출):
    * Operation: Append Row
    * 1번 폼 제출 시 통합 시트에 새로운 행(Row)을 최초 생성.
  * 2번 & 3번 폼 (추가 제출):
    * Operation: Append or Update Row
    * Column to match on: 이메일 주소
    * 1번 폼을 통해 시트에 미리 등록된 이메일을 찾아 해당 사용자의 위치에 취미/음식/영화 정보 추가 기록.
**③ 1번 폼 미제출자 예외 처리 (검문소)**

  * 문제 상황: 1번 폼(이름/이메일)을 쓰지 않고 2,3번 폼을 먼저 쓴 사용자의 경우 메일 발송 금지 처리 필요.
  * 해결 방법:
    1. Get row(s) in sheet 노드로 통합 시트 조회.
    1. If 노드에서 시트 내 이름 항목 존재 여부 확인 ({{ $json['이름'] }} is not empty).
    1. 1번 폼을 쓰지 않은 사용자는 이름 데이터가 없으므로 If 노드에서 False로 판정되어 메일 발송 없이 자동 종료.

### 4.3 💡 트러블슈팅 (주요 에러 및 원인 정리)

**❓ Issue 1: The 'Column to Match On' parameter is required 에러 발생**

  * 원인:
    1. Append or Update Row 사용 시 매칭 기준(Column to match on) 열이 UI상에서 파라미터 등록 미완료 상태였음.
    1. 트리거를 통해 빈 줄(Blank Row, 이메일이 빈값인 행) 데이터가 들어오면서 매칭 대상 값을 찾지 못함.
  * 해결:
    * 트리거 바로 뒤에 Skip empty rows (Filter 노드)를 추가하여 이메일이 있는 정상 데이터만 통과되도록 조치.
**❓ Issue 2: 개별 응답 시트에 상단 빈 공간(행)이 생기는 현상**

  * 원인:
    * 구글 폼 연동 시트는 데이터 추가 시 아래쪽에 '새로운 행을 물리적으로 삽입(Insert)'함.
    * 키보드의 Delete 키는 셀 내부 텍스트만 삭제할 뿐 행 자체를 지우지 않으므로 구글 폼은 빈 행 아래쪽에 응답을 계속 쌓음.
  * 해결:
    * 구글 시트에서 빈 행 번호를 마우스 우클릭 ➔ 행 삭제를 실행해야 물리적으로 아래 행들이 위로 바짝 당겨짐.
