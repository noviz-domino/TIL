## AI 에이전트와 TDD, 개발자의 경쟁력, 그리고 환경변수 관리

> 📍 정리 #1
> 
> 🏷️ 키워드: ai agent, tdd, dotenv, environment variables, secrets management

### AI 에이전트 기획의 중요성과 TDD

- **AI 에이전트와 기획**: AI 에이전트는 자율적으로 판단하고 행동하므로 기획(설계)이 정교하지 않으면 의도하지 않은 동작을 하거나 자원(예산 등)을 낭비하기 쉬움.
    
- **TDD (Test-Driven Development, 테스트 주도 개발)**: 코드를 작성하기 전에 테스트 코드를 먼저 작성하는 개발 방식.
    
    - 진행 순서: `테스트 작성 ➡️ 실패 확인 ➡️ 본 코드 작성 ➡️ 테스트 통과`
        
- **AI 개발에서의 TDD 역할**: AI 에이전트의 환각(Hallucination)이나 잘못된 도구 호출을 방지하기 위해 명확한 동작 검증 기준(Pass/Fail) 역할을 함.
    

### 요즘 채용 시장과 신입 개발자의 경쟁력

- **시장 요구사항 (풀스택 & 문제 해결 능력)**: 단순히 모든 분야의 기술을 완전히 외우는 것보다, 프런트엔드/백엔드를 가리지 않고 주어진 문제를 기술적으로 해결할 수 있는 역량을 요구함.
    
- **경쟁력 확보 전략**:
    
    1. **깊은 기본기 하나 확보**: 백엔드나 프런트엔드 중 하나를 깊게 이해하여 확장 가능성 보여주기.
        
    2. **의사결정 과정 기록**: 문제에 접근한 논리, 기술 선택 이유, 시행착오 및 해결 과정을 TIL이나 PR 등에 문서화하기.
        

### 환경별 환경변수(Key) 분리 관리

- **환경 분리 이유**: 로컬(Local), 개발(Dev), 운영(Prod) 환경의 키값을 각각 다르게 발급받아 관리해야 함.
    
    - **안전성 (사고 방지)**: 개발 및 테스트 중 실수로 프로덕션 DB나 결제 서비스 등 실제 고객 데이터에 영향을 주는 것 방지.
        
    - **비용 및 권한 통제**: 환경별로 API 요청 제한, 접근 권한, 비용 설정을 다르게 적용.
        
- **실무 활용 방식**: `DB_URL`, `OPENAI_API_KEY`, `PAYMENT_SECRET_KEY` 등을 `.env.local`, `.env.development`, `.env.production` 등으로 분리하여 환경에 맞게 주입.
    

### 팀 프로젝트 시 환경변수 공유 방법

- **기본 원칙**: 키가 들어있는 파일(`.env`)은 **절대 Git에 커밋하거나 공유 레포지토리에 올려서는 안 됨**.
    
- **공유 방식**:
    
    1. **소규모 팀**: Git에는 키 이름만 정의된 `.env.example` 파일만 공유하고, 실제 값은 암호 관리 툴(1Password)이나 보안 채널을 통해 개별 전달하여 로컬 `.env`에 저장.
        
    2. **중규모 이상 팀**: Vault, AWS Secrets Manager, Doppler 등 중앙 환경변수/비밀 관리 시스템을 사용해 로그인 및 명령어로 자동 동기화.
        

### ⚠️ 헷갈리기 쉬운 점

- `.env` 파일을 `.gitignore`에 추가하지 않고 GitHub 퍼블릭 레포지토리에 올리면, 자원 탐색 봇에 의해 API 키가 유출되어 심각한 비용 폭탄이나 보안 사고가 발생할 수 있음.
