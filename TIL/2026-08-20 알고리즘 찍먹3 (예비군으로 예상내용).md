### requests의 HTTP 메서드

API의 목적에 따라 적절한 HTTP 메서드를 사용한다. 각 메서드는 `Response` 객체를 반환한다.

  

- `requests.get(url)`: 서버에서 데이터나 목록을 조회할 때 사용한다. 서버 상태를 변경하지 않는 안전한(Safe) 메서드이며 결과가 캐싱될 수 있다. URL에 파라미터가 노출되므로 보안 데이터 전달에는 부적합하다.
    
      
    
- `requests.post(url, json=data)`: 서버에 새로운 데이터를 생성할 때 사용하며 요청 본문(Body)에 JSON 형식으로 전달한다. 실행할 때마다 데이터가 쌓이는 비멱등성(Non-idempotent)을 가지며, 성공 시 보통 `201 Created` 응답을 받는다.
    
      
    
- `requests.patch(url, json=data)`: 기존 데이터 중 일부 필드만 선택적으로 수정할 때 사용한다.
    
      
    
- `requests.put(url, json=data)`: 기존 자원의 모든 필드를 새 데이터로 전체 교체(덮어쓰기)한다. 요청 여러 번 보내도 결과가 동일한 멱등성(Idempotency)을 갖지만, 필드가 누락되면 데이터가 `null`로 바뀌거나 손실될 수 있다.
    
      
    
- `requests.delete(url)`: 서버의 데이터를 삭제할 때 사용한다.
    
      
    

### 요청 옵션 및 리소스 조회

- `params`: URL 뒤에 쿼리 매개변수를 추가하여 보조적인 조건으로 필터링할 때 사용한다. (예: `requests.get(url, params={"userId": 2})` -> `?userId=2`)
    
      
    
- `headers`: 인증 정보, 응답 형식 등 요청의 메타데이터를 전달할 때 사용한다. (예: `headers={"Authorization": "Bearer <token>"}`)
    
      
    
- `중첩 리소스 조회`: 특정 자원에 종속된 정보를 가져올 때 사용한다. (예: `/users/1/posts` 형태)
    
      
    

### 응답 확인 및 예외 처리

응답 본문은 `response.json()`으로 확인하며, 예외 처리 및 상태 코드 확인은 아래 방식을 활용한다.

  

- `raise_for_status()`: 응답 상태 코드가 200~399면 정상 진행하고, 4xx나 5xx 에러면 `HTTPError` 예외를 발생시킨다. 호출하지 않으면 에러 상태 코드여도 예외가 발생하지 않고 `response.status_code`에 해당 코드가 담긴다.
    
      
    
- `Timeout`: 설정한 시간 안에 서버 응답이 오지 않을 때 발생한다. 타임아웃을 명시하지 않으면 프로그램이 무한 대기 상태에 빠질 수 있으므로 실무에서 필수 설정 항목이다.
    
      
    
- `HTTPError`: 서버에 연결되었으나 404, 401, 500 등 에러 상태 코드를 응답할 때 발생한다.
    
      
    
- `RequestException`: `requests` 라이브러리의 요청 관련 예외들을 포함하는 최상위 예외 클래스이다.
    
      
    

### ⚠️ 헷갈리기 쉬운 점

- **params vs json**: `GET` 요청은 요청 본문(Body)이 없으므로 `params`를 사용하고, `POST`/`PATCH`/`PUT`처럼 데이터를 전송할 때는 `json` 매개변수를 사용한다.
    
      
    
- **PUT vs PATCH**: `PUT`은 전체 덮어쓰기이므로 일부 전달을 누락하면 데이터가 삭제되거나 `null`로 변경될 위험이 있다. 특정 항목만 수정할 때는 `PATCH`를 사용하는 것이 안전하다.

### python-dotenv를 활용한 환경변수 관리

보안 정보나 설정을 소스코드에 직접 작성하지 않고 외부 파일(`.env`)에 분리하여 관리하는 방식이다.

  

Python

```
import os
from dotenv import load_dotenv

# .env 파일의 내용을 환경변수로 로드
load_dotenv()

# 로드된 환경변수 참조
debug_mode = os.getenv('DEBUG')
secret_key = os.getenv('SECRET_KEY')
server_port = os.getenv('PORT')
```

- API 키나 비밀번호 같은 민감한 정보가 Git 버전 관리를 통해 GitHub 등에 노출되는 사고를 방지한다.
    
      
    
- 소스코드를 수정하지 않고 `.env` 파일만 교체하여 개발 환경과 실제 운영 환경의 설정을 손쉽게 분리할 수 있다.
    
      
    

### HTTP Authorization 헤더를 이용한 API 인증

외부 API 호출 시 권한 검증을 위해 HTTP 요청 헤더(`headers`)에 인증 토큰을 함께 전달한다.

  

Python

```
import requests
import os
from dotenv import load_dotenv

load_dotenv()

url = "https://api.themoviedb.org/3/movie/now_playing"
token = os.getenv("TMDB_TOKEN")

# Authorization 헤더 설정
my_headers = {
    "Authorization": f"Bearer {token}"
}

try:
    response = requests.get(url, headers=my_headers)
    response.raise_for_status()
    print(response.json())
except Exception as e:
    print('오류 발생:', e)
```

- `Bearer <token>` 형식은 JWT 및 API 인증 토큰 전달 시 사용하는 표준 인증 방식이다.
    
      
    
- 환경변수로 읽어온 토큰을 `headers` 매개변수에 실어 전달하고, `raise_for_status()`를 통해 응답 에러를 예외 처리하는 전형적인 외부 API 연동 패턴이다.
    
      
    

### ⚠️ 헷갈리기 쉬운 점

- **.env 파일 보안 관리**: `.env` 파일에 저장한 실제 토큰 및 비밀값은 절대로 Git 저장소에 커밋해서는 안 되며, `.gitignore` 파일에 `.env`를 추가해 관리해야 한다.

## TMDB API 기초

## 1. API와 Endpoint

API 서버에서 특정 기능이나 데이터를 요청하기 위한 경로를 `Endpoint`라고 한다.

예를 들어 TMDB의 기본 주소가

`https://api.themoviedb.org/3`

이라면 현재 상영 중인 영화의 Endpoint는

`/movie/now_playing`

이다.

전체 요청 주소는 다음과 같다.

`https://api.themoviedb.org/3/movie/now_playing`

### 정리

- 기본 서버 주소: API 서버의 기본 주소
- Endpoint: 어떤 기능이나 데이터를 요청할 것인지 나타내는 경로

예시:

- `/movie/now_playing` : 현재 상영 영화
- `/movie/popular` : 인기 영화
- `/movie/{movie_id}` : 특정 영화의 상세 정보
- `/movie/{movie_id}/credits` : 특정 영화의 배우/스태프 정보

---

## 2. Query Parameter

Query Parameter는 API에 요청하면서 **추가 조건을 전달하는 방법**이다.

예:

`?language=ko-KR&page=2`

각 기호의 의미는 다음과 같다.

- `?` : Query Parameter 시작
- `=` : 이름과 값 연결
- `&` : 다음 조건 추가

따라서 위 주소는 다음과 같은 의미이다.

- `language = ko-KR`
- `page = 2`

즉, **한국어로 2페이지 데이터를 요청한다.**

Python의 `requests`에서는 직접 문자열을 만들지 않고 딕셔너리를 사용할 수 있다.

```python
params = {
    "language": "ko-KR",
    "page": 2
}

response = requests.get(url, params=params)
````

`requests`가 내부적으로 Query Parameter 형식으로 변환해준다.

---

## 3. HTTP Header

Header는 HTTP 요청과 함께 서버에 전달하는 **부가 정보**이다.

간단하게 구분하면 다음과 같다.

- URL / Endpoint → 어디의 어떤 기능을 사용할지
- Query Parameter → 어떤 조건으로 요청할지
- Header → 요청에 추가로 전달할 정보

예를 들어 인증 정보를 Header에 넣을 수 있다.

```
headers = {
    "Authorization": f"Bearer {token}"
}
```

그리고 다음과 같이 요청한다.

```
response = requests.get(url, headers=headers)
```

---

## 4. Bearer Token

Bearer Token은 토큰을 이용해 사용자를 인증하는 방식이다.

형식:

`Authorization: Bearer 토큰값`

예를 들어:

```
token = "ABC123"

headers = {
    "Authorization": f"Bearer {token}"
}
```

실제 Header 값은 다음과 같다.

`Authorization: Bearer ABC123`

Bearer Token은 인증에 사용되므로 외부에 노출되지 않도록 관리해야 한다.

---

## 5. 환경변수

환경변수는 프로그램 외부에서 관리할 수 있는 **이름=값 형태의 설정값**이다.

예:

```
TMDB_TOKEN=abc123
PORT=8000
DEBUG=True
```

환경변수가 반드시 `.env` 파일에 저장되는 것은 아니다.

운영체제에 직접 등록할 수도 있지만, 개발할 때 편하게 관리하기 위해 `.env` 파일을 많이 사용한다.

---

## 6. `.env`

`.env` 파일은 환경변수로 사용할 값을 저장할 때 자주 사용한다.

예:

```
TMDB_TOKEN=abc123
TMDB_API_KEY=xyz789
```

중요한 점은 `.env` 파일을 만들었다고 자동으로 Python에서 읽을 수 있는 것은 아니라는 것이다.

---

## 7. `load_dotenv()`

```
from dotenv import load_dotenv

load_dotenv()
```

`load_dotenv()`는 기본적으로 `.env` 파일을 찾아 그 안의 값을 현재 프로그램에서 환경변수처럼 사용할 수 있도록 불러온다.

다른 파일을 직접 지정할 수도 있다.

```
load_dotenv("my_secret.env")
```

---

## 8. `os.getenv()`

환경변수의 값을 가져올 때 사용한다.

```
import os

token = os.getenv("TMDB_TOKEN")
```

구분하면:

- `TMDB_TOKEN` → 환경변수 이름
- `os.getenv("TMDB_TOKEN")` → 환경변수의 값을 가져옴
- `token` → 가져온 값을 저장하는 Python 변수

---

## 9. `.env.example`

`.env.example`은 실제 비밀값을 저장하는 파일이 아니다.

프로젝트에서 어떤 환경변수가 필요한지를 알려주는 **견본 파일**이다.

예:

```
TMDB_TOKEN=
TMDB_API_KEY=
```

이 파일을 참고해서 실제 `.env` 파일을 만들고 자신의 값을 입력한다.

---

## 10. HTTPS와 비밀값

HTTPS를 사용하면 HTTP 요청이 전송되는 동안 Header 등을 포함한 통신 내용이 암호화된다.

하지만 토큰을 코드에 직접 작성하면 HTTPS와 관계없이 코드가 유출될 때 같이 노출될 수 있다.

잘못된 예:

```
token = "실제_토큰값"
```

따라서 일반적으로 다음 역할을 나눠서 사용한다.

- `.env` → 비밀값을 코드 밖에 보관
- `os.getenv()` → 비밀값 가져오기
- Header → 서버에 인증정보 전달
- HTTPS → 전송 중 통신 암호화

---

## 11. `requests.get()`

GET 요청을 서버에 보낼 때 사용한다.

```
response = requests.get(url)
```

Header와 Query Parameter를 동시에 사용할 수도 있다.

```
response = requests.get(
    url,
    headers=headers,
    params=params
)
```

의미:

> `url`로 GET 요청을 보내면서  
> `headers`의 부가 정보와  
> `params`의 요청 조건을 함께 전달하고  
> 서버 응답을 `response`에 저장한다.

---

## 12. JSON과 `results`

API 서버에서 받은 JSON 응답은 다음과 같이 Python 객체로 변환할 수 있다.

```
data = response.json()
```

TMDB의 데이터가 다음과 같다고 가정하면:

```
data = {
    "page": 1,
    "results": [
        {
            "title": "영화 A",
            "vote_average": 7.8
        },
        {
            "title": "영화 B",
            "vote_average": 9.1
        }
    ]
}
```

영화 목록만 가져오려면:

```
results = data.get("results")
```

`results`는 **딕셔너리가 들어있는 리스트**이다.

```
type(results)
# list

type(results[0])
# dict
```

따라서:

```
for movie in results:
    print(movie)
```

라고 하면 `movie`에는 영화 하나를 나타내는 딕셔너리가 하나씩 들어온다.

## 13. 예외 처리

기본 구조:

```
try:
    # 실행할 코드

except Exception as e:
    # 오류가 발생했을 때 실행
```

### `try`

코드를 우선 실행한다.

### `except`

`try`에서 예외가 발생하면 실행한다.

### `Exception`

일반적인 여러 예외를 넓게 잡는 클래스이다.

### `as e`

발생한 예외 객체를 `e`라는 변수에 저장한다.

```
try:
    number = int("hello")

except Exception as e:
    print(e)
```

`e`라는 이름은 정해져 있는 것이 아니다.

```
except Exception as error:
    print(error)
```

처럼 작성해도 된다.
