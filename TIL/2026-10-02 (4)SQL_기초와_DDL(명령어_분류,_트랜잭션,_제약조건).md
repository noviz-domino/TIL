## 주제 1: SQL이란

- **SQL(Structured Query Language)** 은 데이터베이스를 관리하고 데이터를 처리하기 위한 **표준 프로그래밍 언어**이다.
- 데이터의 **삽입, 조회, 수정, 삭제** 등의 작업을 수행한다.

### SQL과 DBMS

- SQL은 **표준**이 있어서 DBMS가 달라도 기본적인 개념과 주요 명령어의 사용 방식은 공통적이다.
- 다만 **데이터 타입, 내장 함수, 자동 증가 값 설정** 등 세부 문법과 동작은 DBMS마다 다를 수 있다.
- 이 수업의 SQL 설명과 예제는 **PostgreSQL을 기준**으로 한다.

### 수업에서 안내된 실습 환경

- 수업에서 **PostgreSQL을 설치해서 실습**한다.
- 설치 버전은 **17**을 받으라고 안내되었다. 구버전이 더 안정적이라는 이유이다.
- 설치 후 **VS Code에 연결**했다. (이후 실습은 별도 세션에서 진행한다.)

> ➕ **더 알아두기 — PostgreSQL과 RAG 실습, 설치 팁**
> (수업에서 나온 내용이 아니라 대화 중 보충한 일반 지식이다.)
>
> - 처음에 "RAG 실습이라면 벡터 DB일 것 같다"고 추측했으나, 실습 DB는 **PostgreSQL**로 안내되었다. PostgreSQL은 관계형 DB(RDB)이다. 다만 **pgvector**가 PostgreSQL에 벡터 저장과 유사 검색 기능을 붙인 것이라, PostgreSQL로도 RAG를 할 수 있다. 실습에서 pgvector까지 쓰는지는 강사님 설명으로 확인해야 한다.
> - 설치할 때 **`postgres` 관리자 비밀번호**를 정하게 되므로 잊지 않게 적어 둔다. 기본 **포트 번호는 5432**로 알고 있다.

> 📝 **기사 시험 포인트** (정보처리기사, 확실도: 중간)
> PostgreSQL은 오픈소스 관계형 DBMS로, 시험에서는 Oracle, MySQL과 같은 **DBMS 예시**로 나오는 정도로 알고 있다. 이름 자체에 따로 외울 개념은 없는 것으로 알고 있다.

## 주제 2: 기본 규칙

```sql
SELECT first_name, last_name
FROM employees
WHERE department_id = 100;
```

- SQL 문은 **세미콜론(`;`)** 으로 구분하며, 예제에서는 각 문장 끝에 세미콜론을 붙인다.
- 여러 줄로 작성할 수 있으며, 가독성을 위해 적절한 **들여쓰기**를 권장한다.
- **SQL 키워드는 대소문자를 구분하지 않는다.** `SELECT`와 `select`는 동일하게 동작한다. 하지만 가독성을 위해 키워드는 **대문자로 작성하는 것이 관례**이다.

### 주석 작성

`--` 또는 `/* */`을 활용한다.

```sql
-- 한 줄 주석

SELECT * FROM employees; -- 이렇게 뒤에 작성도 가능

/* 여러 줄
주석은 */
```

### 공백과 줄바꿈

- SQL 문법 요소 사이에는 가독성을 위해 **공백과 줄바꿈**을 사용할 수 있다.
- **문자열이나 큰따옴표로 감싼 이름 안의 공백**은 값이나 이름의 일부이므로 유지된다.

```sql
-- 아래 세 쿼리는 동일하게 동작
SELECT * FROM employees WHERE salary > 50000;

SELECT *
FROM employees
WHERE salary > 50000;

SELECT * FROM employees
WHERE salary > 50000;
```

## 주제 3: 이름과 값 작성

- **테이블명과 컬럼명**은 `user_profile`처럼 **소문자와 밑줄을 사용하는 snake_case**로 작성하는 것을 권장한다.
- SQL 문법에서 사용하는 **예약어는 이름으로 사용하지 않는 것**이 좋다. 꼭 사용해야 한다면 **큰따옴표(`"`)** 로 감싼다.
- PostgreSQL은 **큰따옴표 없이 작성한 이름을 소문자로 처리**한다. **큰따옴표로 감싼 이름은 대소문자를 구분**한다.
- **문자열과 날짜 값은 작은따옴표(`'`)** 로 감싸고, **숫자 값은 따옴표 없이** 작성한다.

> ➕ **더 알아두기 — 대소문자는 무엇이 구분되고 무엇이 안 되는가**
> (수업 설명을 한 표로 정리하고 문자열 값 이야기를 보탠 것이다.)
>
> | 대상 | 대소문자 구분? | 예 |
> |---|---|---|
> | **SQL 키워드** | 구분 안 함 | `SELECT` = `select` = `Select` |
> | **이름**(테이블명, 컬럼명), 큰따옴표 **없이** | PostgreSQL이 **소문자로 처리** | `User_Profile` → `user_profile` |
> | **이름**, 큰따옴표로 **감쌈** | **구분함** | `"User_Profile"` ≠ `"user_profile"` |
> | **문자열 값** | 구분함 (PostgreSQL 기본 동작으로 알고 있다) | `'Kim'` ≠ `'kim'` |
>
> - 대문자는 **규칙이 아니라 읽기 편하려는 관례**이다. 소문자로 써도 동작은 같다.
> - 이름에 큰따옴표를 쓰면 이후에도 항상 같은 대소문자로 큰따옴표와 함께 써야 해서 불편하다. 수업이 소문자 snake_case를 권장하는 이유이다.

> ♻️ 처음엔 **"키워드를 대문자로 쓴다"는 말을 명령어(`SELECT` 등)만 가리키는 것**으로 알았으나, **명령어는 키워드의 일부**이고 `FROM`, `WHERE` 같은 문법 단어도 키워드이다.

> ➕ **더 알아두기 — 키워드와 내가 지은 이름 구분하기**
> SQL 문장을 읽을 때는 **키워드 / 내가 지은 이름 / 연산자 / 값** 네 가지로 나눠 읽는다.
>
> ```sql
> SELECT name FROM products WHERE price > 5000;
> ```
>
> | 단어 | 정체 |
> |---|---|
> | `SELECT`, `FROM`, `WHERE` | **키워드** (3개) |
> | `name`, `price` | 컬럼 이름 (속성) |
> | `products` | 테이블 이름 |
> | `>` | 연산자 (키워드가 아니다) |
> | `5000` | 값 |
>
> "products 테이블에서, price가 5000보다 큰 행의, name을 조회한다"로 읽는다. 예약어는 SQL이 이미 용도를 정해 둔 단어(키워드)라서 이름으로 쓰면 헷갈린다. 키워드와 예약어는 엄밀히는 구분이 있다고 알고 있으나 지금은 "SQL이 미리 쓰는 단어"로 같이 생각해도 된다.

> ➕ **더 알아두기 — 컬럼, 속성(애트리뷰트), 열은 같은 말이다**
> 같은 대상을 부르는 이름이 여럿이다. **컬럼은 column의 한국어 발음**이라 열과 완전히 같고, **속성(Attribute)** 은 "대상이 가지는 정보"라는 **설계 쪽 표현**이며 DB에서는 열(컬럼)로 만들어진다. 엔티티와 테이블이 "설계 말 / DB 말" 관계였던 것처럼 속성과 열도 같은 관계이다. 정리하면 **"세로 한 줄 = 열 = 컬럼 = 속성 = 필드", "가로 한 줄 = 행 = 레코드 = 튜플"** 이다.

> 📝 **기사 시험 포인트** (정보처리기사, 확실도: 높음)
> 시험에서는 **관계형 데이터 모델**의 용어로 나온다.
>
> | 시험 용어 | 우리가 부르던 말 |
> |---|---|
> | 릴레이션(Relation) | 테이블 |
> | 튜플(Tuple) | 행, 레코드 |
> | 속성(Attribute) | 열, 컬럼 |
> | **차수(Degree)** | **속성(열)의 개수** |
> | **카디널리티(Cardinality)** | **튜플(행)의 개수** |
>
> 카디널리티는 ERD에서 "1:N 같은 **관계의 대응 수**"를 말할 때도 쓰는 말이라, **어디서 나온 말이냐에 따라 뜻이 다르다.** 릴레이션 이야기에서는 "행의 개수"이다. (이 구분은 수업에 나오지 않았고 일반 지식이다.)

## 주제 4: SQL 명령어 분류

| 분류 | 뜻 | 명령어 |
|---|---|---|
| **DDL** (Data Definition Language, 데이터 정의어) | 데이터베이스 **구조**를 정의하고 변경 | CREATE, ALTER, DROP, TRUNCATE |
| **DML** (Data Manipulation Language, 데이터 조작어) | 데이터를 조작(입력, 수정, 삭제, 조회) | INSERT, UPDATE, DELETE, SELECT |
| **DCL** (Data Control Language, 데이터 제어어) | 데이터베이스의 **접근 권한**을 제어 | GRANT, REVOKE |
| **TCL** (Transaction Control Language, 트랜잭션 제어어) | 트랜잭션을 시작하거나 변경을 **확정·취소** | BEGIN, COMMIT, ROLLBACK |

- `SELECT`를 **DQL(Data Query Language, 데이터 질의어)** 로 따로 분류하기도 한다.

> ➕ **더 알아두기 — 분류를 외우는 요령**
> **"무엇을 건드리나"** 로 가른다. 구조를 건드리면 DDL(정의), 데이터 내용을 건드리면 DML(조작), 권한을 건드리면 DCL(제어), 변경을 확정·취소하면 TCL(트랜잭션)이다.

> 📝 **기사 시험 포인트** (정보처리기사, 확실도는 항목마다 표시)
>
> - **DDL / DML / DCL / TCL 분류**는 SQL 영역의 기본이다. (확실도: 높음) 명령어를 어느 분류에 넣는지 묻는 형태로 알고 있다. 한글 용어(**정의어 / 조작어 / 제어어**)도 같이 외운다.
> - 시험에서는 **SELECT를 DML에 포함**하는 분류가 일반적이다. 수업도 "DQL로 따로 분류하기도 한다"고 했으니 두 방식이 있다는 것까지 알아 둔다.
> - **TCL은 COMMIT, ROLLBACK, SAVEPOINT**로 정리되는 경우가 많은 것으로 알고 있다. (확실도: 중간. 수업의 `BEGIN`과 달리 `SAVEPOINT`(되돌릴 지점 표시)가 같이 나오며, 수업에는 없다.) 표준 SQL에서 트랜잭션 시작은 `START TRANSACTION`이고 `BEGIN`은 PostgreSQL 등에서 쓰는 형태로 알고 있다.

> 📝 **기사 시험 포인트** (정보보안기사, 확실도: 중간)
> DCL의 `GRANT`/`REVOKE`로 권한을 주고 회수하는 것은 DB **접근 통제**와 이어진다. 필요한 권한만 주는 **최소 권한 원칙**과 같이 기억한다. (정보보안기사에서 DB 접근 통제가 어떤 형태로 출제되는지는 확인하지 못했다.)

## 주제 5: 트랜잭션

- **하나 이상의 SQL 작업을 하나로 묶어 처리하는 논리적 작업 단위**이다.
- 예: A가 B에게 5만 원을 송금하려면 **A 계좌에서 출금하고 B 계좌에 입금**해야 한다. 출금과 입금을 하나의 트랜잭션으로 묶으면 두 작업의 변경을 **모두 반영하거나 모두 취소**할 수 있다. 이를 통해 **출금만 반영되고 입금은 반영되지 않는 상태를 방지**한다.
- **`BEGIN`** 은 트랜잭션을 시작하고, **`COMMIT`** 은 변경을 확정하며, **`ROLLBACK`** 은 변경을 취소한다.

> ➕ **더 알아두기 — 트랜잭션을 처음부터 쉽게**
> (수업에서 나온 설명이 아니라 대화 중 정리한 설명이다.)
>
> **1. 문제 상황**: 송금은 사람 눈에는 한 가지 일이지만 DB에서는 작업이 두 개(출금, 입금)로 나뉜다.
>
> | 순서 | 상태 | A 잔액 | B 잔액 |
> |---|---|---|---|
> | 시작 | | 10만 원 | 0원 |
> | ① 출금 | 출금만 반영 | 5만 원 | 0원 |
> | ② 입금 | 입금까지 반영 | 5만 원 | 5만 원 |
>
> ①과 ② 사이에서 서버가 꺼지면 **5만 원이 사라진 상태**가 된다. 전체 돈의 합이 줄어, 데이터가 정확하지도 서로 맞지도 않게 된다. 이처럼 **데이터가 정확하고 서로 모순이 없는 상태를 무결성(Integrity)** 이라고 하며, 트랜잭션은 중간에 끊겨서 데이터가 어긋나는 것을 막는 장치이다.
>
> **2. 해결**: ①②를 한 덩어리로 묶고 규칙을 하나로 정한다. **"덩어리 안의 작업은 전부 성공하거나, 전부 없던 일로 한다."** 모두 성공하면 `COMMIT`으로 확정하고, 하나라도 실패하면 `ROLLBACK`으로 전부 취소한다.
>
> **3. 오류가 났을 때의 단계**
>
> | 단계 | 상태 | A 잔액 |
> |---|---|---|
> | `BEGIN` | 묶음 시작 | 10만 원 |
> | ① 출금 실행 | 아직 **임시** 상태 (확정 전) | 5만 원 *(임시)* |
> | ② 입금 중 **오류** | 실패 | |
> | `ROLLBACK` | 변경을 전부 취소 | **10만 원 (원래대로)** |
>
> `COMMIT` 전의 변경은 **임시 상태**라서 `ROLLBACK`하면 없던 일이 되고, `COMMIT`하면 그때서야 진짜로 저장된다. **오류가 나면 `ROLLBACK`, 성공하면 `COMMIT`, 둘 중 하나로 반드시 닫는다.**
>
> **4. 코드 모양** (PostgreSQL 예시. `UPDATE`, `WHERE`는 아직 배우지 않았을 수 있다.)
>
> ```sql
> BEGIN;
> UPDATE accounts SET balance = balance - 50000 WHERE name = 'A';  -- ① 출금
> UPDATE accounts SET balance = balance + 50000 WHERE name = 'B';  -- ② 입금
> COMMIT;   -- 둘 다 성공했으니 확정
> ```
>
> **5. 비유**: 장바구니에 담는 동안은 취소할 수 있고(`ROLLBACK`), 결제 버튼을 누르면 확정(`COMMIT`)이다. 그 사이에 여러 작업이 끼어 있어도 결과는 "결제 성공" 또는 "결제 안 됨" 두 가지뿐이다.
> RDB가 은행 이체처럼 전부 성공하거나 전부 취소되는 트랜잭션에 강하다는 앞의 비교(RDB는 회계 장부, 벡터 DB는 사서)가 이 내용이다.

> ♻️ 처음엔 **`BEGIN`부터 `ROLLBACK`까지를 하나씩 입력**하다가 문제가 생긴 것을 확인한 뒤 `ROLLBACK`을 쳐야 하고, 묶어서 보내면 안 된다고 이해했으나, **묶어서 한꺼번에 보내도 된다.** 하나씩 입력하는 것은 사람이 터미널에서 직접 연습할 때의 모습이고, 실제 서비스에서는 **프로그램이 오류를 감지해 자동으로 `ROLLBACK`** 을 보낸다.

> ➕ **더 알아두기 — 프로그램에서의 트랜잭션과 PostgreSQL의 오류 동작**
>
> 의사 코드로 보면 **코드가 "오류가 났나?"를 판단하고, 오류가 나면 `ROLLBACK`을 호출**한다. 파이썬으로 DB를 다룰 때 곧 보게 될 가능성이 크다.
>
> ```python
> try:
>     BEGIN
>     출금
>     입금
>     COMMIT       # 전부 성공하면 확정
> except 오류:
>     ROLLBACK     # 하나라도 실패하면 전부 취소
> ```
>
> PostgreSQL은 트랜잭션 안에서 SQL이 오류가 나면 그 트랜잭션을 **"실패 상태"** 로 표시하고, 이후 명령은 `ROLLBACK`으로 끝낼 때까지 **무시**한다. 이때 `COMMIT`을 보내도 실제로는 `ROLLBACK`처럼 처리되는 것으로 알고 있다. 그래서 묶어서 보냈을 때 중간에 오류가 나도 엉뚱하게 확정되지 않는다.
> `ROLLBACK`은 "사람이 알아챈 다음 치는 명령"이 아니라 **"실패했을 때 실행하도록 정해 둔 명령"** 이다. 중간에 끊길 때를 대비해 **되돌리는 길을 열어 두는 것**이 트랜잭션을 쓰는 이유이다.

> 📝 **기사 시험 포인트** (정보처리기사, 확실도: 높음)
>
> **트랜잭션의 4가지 성질, ACID**
>
> | 성질 | 영문 | 뜻 |
> |---|---|---|
> | 원자성 | Atomicity | 모두 반영되거나 모두 취소 (all or nothing) |
> | 일관성 | Consistency | 트랜잭션 전후로 DB가 일관된 상태 |
> | 격리성 | Isolation | 동시에 실행돼도 서로 영향을 주지 않음 |
> | 지속성 | Durability | 확정된 결과는 장애가 나도 유지 |
>
> 수업의 송금 예시("출금만 반영되고 입금은 반영되지 않는 상태를 방지")는 **원자성**의 대표 예이다. 앞의 [NoSQL 글](2026-10-02%20(3)비관계형_데이터베이스(NoSQL,_키-값,_문서,_그래프,_와이드_컬럼).md)의 BASE와 비교해 외운다.

## 주제 6: DDL — 구조를 정의하고 변경하는 명령어

- **DDL(Data Definition Language, 데이터 정의어)** 은 데이터베이스 구조를 정의하고 변경하는 명령어이다.

### CREATE (생성)

**데이터베이스 생성**

```sql
CREATE DATABASE 데이터베이스이름;
```

```sql
CREATE DATABASE demodb;
```

**테이블 생성**

```sql
CREATE TABLE 테이블명 (
    컬럼명1 데이터타입 [제약조건],
    컬럼명2 데이터타입 [제약조건],
    ...
);
```

### 주요 데이터 타입

| 분류 | 타입 | 설명 |
|---|---|---|
| 숫자 | `INT` | 정수. 인원수, 수량 등에 사용 |
| 숫자 | `BIGINT` | INT보다 넓은 범위의 정수 |
| 숫자 | `DECIMAL(전체자리수, 소수자리수)` | 전체 자릿수와 소수 자릿수를 지정하는 **정확한** 십진수. 금액 등에 사용 |
| 숫자 | `DOUBLE PRECISION` | **근삿값**으로 저장하는 부동소수점 수. 측정값 등에 사용하며 오차가 생길 수 있음 |
| 문자 | `CHAR(n)` | **고정 길이** 문자열. 짧은 값은 남은 길이를 공백으로 채움 |
| 문자 | `VARCHAR(n)` | 최대 n자까지 저장하는 **가변 길이** 문자열 |
| 문자 | `TEXT` | 길이를 미리 지정하지 않는 문자열. 본문, 설명 등에 사용 |
| 날짜/시간 | `DATE` | 날짜. 예: 2026-10-01 |
| 날짜/시간 | `TIME` | 시간. 예: 14:30:00 |
| 날짜/시간 | `TIMESTAMP` | 날짜와 시간. 예: 2026-10-01 14:30:00 |
| 논리 | `BOOLEAN` | 참(TRUE) 또는 거짓(FALSE). 활성화 여부 등에 사용 |

- `DECIMAL`과 `NUMERIC`은 PostgreSQL에서 **같은 타입**이다.
- `DECIMAL(10, 2)`는 전체 10자리 중 소수점 아래 2자리를 사용하므로 **정수 부분은 최대 8자리**이다. 소수점 아래 2자리를 넘는 값은 **반올림**된다.
- `TIMESTAMP`는 기본적으로 **시간대 정보를 포함하지 않는다.**

### 제약조건

- **제약조건**은 테이블에 저장할 데이터가 지켜야 하는 **규칙**이다.
- **NULL**은 값이 없거나 알려지지 않았음을 나타낸다.

| 제약조건 | 설명 | 컬럼 정의 예시 |
|---|---|---|
| `PRIMARY KEY` | 각 행을 구분하는 기본키. **중복과 NULL을 허용하지 않음** | `id VARCHAR(7) PRIMARY KEY` |
| `NOT NULL` | NULL을 허용하지 않음 | `name VARCHAR(10) NOT NULL` |
| `UNIQUE` | 값의 중복을 허용하지 않음 | `email VARCHAR(100) UNIQUE` |
| `CHECK` | 저장할 값이 주어진 조건을 만족하도록 제한 | `grade INT CHECK (grade BETWEEN 1 AND 4)` |
| `FOREIGN KEY` | 참조 대상 테이블에 **존재하는 키 값만** 저장하도록 제한 | `student_id VARCHAR(7) REFERENCES student(id)` |

- 기본키는 **테이블당 하나**이며, 여러 컬럼을 묶어 하나의 기본키로 지정할 수도 있다.
- PostgreSQL의 `UNIQUE`는 기본적으로 **여러 행의 NULL을 허용**한다.
- `CHECK`와 외래키만으로는 NULL을 막지 못한다. 값을 반드시 입력받으려면 **`NOT NULL`을 함께 지정**한다.

> 📝 **기사 시험 포인트** (정보처리기사, 확실도: 높음)
> 제약조건은 **무결성**과 짝지어 외운다. 무결성 제약 조건의 대표 3가지는 다음과 같이 알고 있다. (정확한 정의는 시험 교재 표현으로 한 번 더 확인한다.)
>
> | 무결성 | 뜻 | 이 수업에서 만난 것 |
> |---|---|---|
> | **개체 무결성** | 기본 키는 **NULL이 아니고 유일** | `PRIMARY KEY` |
> | **참조 무결성** | 외래 키는 참조하는 테이블에 **존재하는 값**이거나 NULL | `FOREIGN KEY` |
> | **도메인 무결성** | 열의 값은 **정해진 범위·타입** 안에 있어야 함 | 데이터 타입, `CHECK` |

### 외래키 (FOREIGN KEY)

- 외래키는 참조 대상 테이블의 키와 연결하여, **존재하지 않는 대상을 가리키는 데이터가 저장되지 않도록** 하는 제약조건이다. 이를 **참조 무결성**이라고 한다.
- 일반적으로 참조 대상은 **`PRIMARY KEY` 또는 `UNIQUE`가 지정된 컬럼**이다.
- 아래 예제에서 `attendance.student_id`는 `student.id`를 참조한다.
  - `student`: 학생 정보를 저장하는 **참조 대상 테이블**
  - `attendance`: 학생의 출결 정보를 저장하는 **참조하는 테이블**
- 컬럼 정의에 **`REFERENCES 참조테이블(참조컬럼)`** 을 붙여 외래키를 지정한다.

```sql
student_id VARCHAR(7) REFERENCES student(id)
```

위 코드는 `CREATE TABLE`의 괄호 안에 작성하는 **컬럼 정의**이다. 같은 외래키를 **테이블 수준에서 따로** 지정할 수도 있다.

```sql
student_id VARCHAR(7),
FOREIGN KEY (student_id) REFERENCES student(id)
```

- `student.id`에 `'2024001'`이 있으면 해당 학번의 출결을 저장할 수 있다. **없는 학번을 `attendance.student_id`에 입력하거나 그 값으로 변경하면 오류**가 발생한다.
- 한 학생의 여러 출결 기록이 같은 학번을 참조할 수 있다. **외래키 자체는 값의 중복을 막지 않는다.** (1:N 관계)
- **`NOT NULL`을 지정하지 않으면 `student_id`에 NULL도 저장**할 수 있다.
- **별도 옵션이 없으면** 출결 기록이 참조 중인 학생을 **삭제하거나 그 학번을 변경**할 때 오류가 발생한다. 기존 출결 기록이 참조할 학생이 사라지는 것을 막기 위해서이다.

> ➕ **더 알아두기 — 외래키 설명 검증과 필수/선택 관계**
> (다른 곳에서 받은 설명을 PostgreSQL 동작과 맞춰 확인한 내용이다. 실제 에러 메시지는 직접 실행해서 확인하는 것이 가장 확실하다.)
>
> - `REFERENCES student (id)`는 "지금 만드는 `student_id` 컬럼에는 `student` 테이블의 `id`에 있는 값만 넣겠다"는 뜻이다. 없는 값을 넣으면 **외래키 위반 오류**(Foreign Key Violation)가 나고, `NULL`은 "아직 누구 출석인지 모름"을 뜻하므로 `NOT NULL`이 없으면 에러 없이 들어간다.
> - 방향은 두 가지이다. **없는 값을 넣는 쪽**(자식에 부모에 없는 값)과 **참조되고 있는 부모를 삭제·변경하는 쪽**(수업 설명 마지막 불릿)이 모두 막힌다. 별도 옵션(`ON DELETE ...` 등)은 수업에서 다루는지 모르겠다.
> - **`NOT NULL` 여부는 ERD의 "필수/선택"과 이어진다.** FK 열에 `NOT NULL`을 붙이면 "반드시 하나에 속해야 한다" = **필수 관계**이고, `NULL`을 허용하면 "아직 속하지 않을 수도 있다" = **선택 관계**이다. 출결 테이블의 `student_id`는 `NOT NULL`이 없으므로 선택적 관계이다. (이 대응은 개념을 연결해 본 것이며 수업에서 같은 설명이 나왔는지는 모르겠다.)

### 기본값과 자동 생성 값

- **`DEFAULT`** 는 제약조건이 아니라 **값을 생략했을 때 사용할 기본값**을 설정하는 기능이다. 예: `grade INT DEFAULT 1`
- 값을 **명시적으로 NULL로 넣으면 기본값으로 바뀌지 않는다.**
- **`GENERATED ALWAYS AS IDENTITY`** 는 정수 컬럼의 값을 **자동으로 생성**한다. 예: `attendance_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY`
- 자동 생성만으로 중복을 막는 것은 아니므로, 기본키로 사용할 때는 **`PRIMARY KEY`를 함께 지정**한다.

### 테이블 생성 예제

```sql
-- 기본적인 테이블 생성
CREATE TABLE student (
    id VARCHAR(7) PRIMARY KEY,
    name VARCHAR(10),
    grade INT,
    major VARCHAR(20)
);
```

```sql
-- 외래키가 있는 테이블 생성
CREATE TABLE attendance (
    attendance_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    student_id VARCHAR(7) REFERENCES student(id),
    date DATE,
    status VARCHAR(10)
);
```

> 📝 **기사 시험 포인트** (정보처리기사, 확실도: 높음)
> **DELETE / TRUNCATE / DROP의 차이**는 시험에서 자주 비교되는 것으로 알고 있다.
>
> | 명령 | 분류 | 하는 일 |
> |---|---|---|
> | `DELETE` | DML | **조건에 맞는 행**을 삭제 (조건 없이 쓰면 전체 행). 테이블 구조는 유지 |
> | `TRUNCATE` | **DDL** | **모든 행**을 삭제. 테이블 구조는 유지 |
> | `DROP` | DDL | **테이블 구조까지** 삭제 |
>
> 수업의 DDL 표에서 `TRUNCATE`는 이름이 "데이터를 지우는 것"처럼 보여도 **DDL**이다. `DELETE`는 수업에 아직 나오지 않았고, `DML`이다. 되돌릴 수 있는지(ROLLBACK 가능 여부)는 DBMS마다 다른 것으로 알고 있어 여기서는 다루지 않는다.

## 정리

- **SQL**은 DB를 관리하고 데이터를 처리하는 표준 언어이다. 표준이 있어 DBMS가 달라도 기본은 같지만 세부 문법은 다르며, 이 수업은 **PostgreSQL** 기준이다. (설치 버전은 17 안내)
- **기본 규칙**: 문장 끝은 `;`, **키워드는 대소문자 구분 없음(대문자는 관례)**, 주석은 `--`와 `/* */`, 이름은 소문자 snake_case, 문자열·날짜는 작은따옴표, 숫자는 따옴표 없음. PostgreSQL은 큰따옴표 없는 이름을 소문자로 처리하고 큰따옴표 이름은 대소문자를 구분한다.
- **명령어 분류**: DDL(구조: CREATE, ALTER, DROP, TRUNCATE) / DML(데이터: INSERT, UPDATE, DELETE, SELECT) / DCL(권한: GRANT, REVOKE) / TCL(트랜잭션: BEGIN, COMMIT, ROLLBACK)
- **트랜잭션**은 여러 SQL을 하나로 묶은 논리적 작업 단위이다. 전부 반영(`COMMIT`)하거나 전부 취소(`ROLLBACK`)해서 송금처럼 중간 상태가 남지 않게 한다.
- **DDL**
  - `CREATE DATABASE` / `CREATE TABLE 테이블명 (컬럼명 타입 [제약조건], ...)`
  - 주요 타입: INT, BIGINT, DECIMAL(정확), DOUBLE PRECISION(근삿값), CHAR(고정), VARCHAR(가변), TEXT, DATE, TIME, TIMESTAMP, BOOLEAN
  - 제약조건: PRIMARY KEY(중복·NULL 불가), NOT NULL, UNIQUE, CHECK, FOREIGN KEY(참조 무결성). CHECK와 FK만으로는 NULL을 막지 못하므로 값이 꼭 필요하면 NOT NULL을 함께 지정한다.
  - **외래키**는 존재하지 않는 대상을 가리키는 데이터를 막는다(참조 무결성). 참조 대상은 보통 PRIMARY KEY나 UNIQUE 컬럼이고, 같은 값을 여러 행이 참조할 수 있으며, 별도 옵션이 없으면 참조 중인 부모를 삭제·변경할 수 없다.
  - `DEFAULT`(값 생략 시 기본값), `GENERATED ALWAYS AS IDENTITY`(자동 생성, 기본키로 쓰려면 PRIMARY KEY 함께)
  - `ALTER`: 컬럼 추가 `ADD`, 이름 변경 `RENAME COLUMN ... TO`, 타입 변경 `ALTER COLUMN ... TYPE`, 삭제 `DROP COLUMN`
  - `DROP`: 데이터베이스·테이블 삭제 / `TRUNCATE`: 테이블의 데이터 전체 삭제
