## 1. 파이썬 함수의 개념과 특징

### 1.1 함수란?

함수는 특정 작업을 수행하는 코드 조각을 하나로 묶어둔 것이다.

수업 중이나 실무에서 함수를 쓰는 가장 큰 이유는 **중복을 줄이고 재사용하기 위해서**다. 같은 로직을 여러 번 쓸 때 매번 다시 적지 않고, 함수 이름만 불러서 깔끔하게 실행한다.

나중에 프로젝트가 커지면 '로그인 기능', '결제 처리'처럼 역할을 단위별로 나누어 유지보수할 때 핵심적으로 마주치게 된다.

### 1.2 내장 함수 (Built-in Function)

`print()`는 파이썬이 기본으로 제공하는 내장 함수(Built-in Function)다.

직접 함수를 정의하지 않아도, 파이썬을 설치하면 바로 쓸 수 있게 준비되어 있다. 실무에서는 화면에 값을 출력해서 코드 실행 중간 과정을 확인(디버깅)하거나, 서버 로그를 기록할 때 사용한다.

`len()`, `type()` 같은 것들도 전부 파이썬이 미리 만들어둔 내장 함수다.

### 1.3 함수의 입력(Input)과 출력(Output)

입력값(매개변수/Parameter)을 받아 내부 로직을 거쳐 결과값(반환값/Return)을 내놓는 것이 함수의 표준 형태다.

하지만 **모든 함수가 반드시 인풋이나 아웃풋을 필요로 하는 것은 아니며, 인풋과 아웃풋 모두 선택 사항**이다.

- **둘 다 없는 경우**: 단순 안내문 출력처럼 특정 명령들을 순서대로 실행하고 끝나는 함수
- **인풋만 있는 경우**: `print()`나 DB 데이터 저장처럼 값을 전달받아 처리하지만 결과는 돌려주지 않는 함수 (`print()`는 화면에 글자를 보여줄 뿐 실제 반환값은 `None`)
- **아웃풋만 있는 경우**: `datetime.now()`처럼 인풋 없이 고정된 결과나 현재 상태를 가져오는 함수
- **둘 다 있는 경우**: 두 수를 더하는 함수처럼 입력값을 받아 계산 후 결과를 돌려주는 함수

실무에서는 '이 함수가 결과값(return)을 전달해주는지, 아니면 단순 실행만 하고 끝나는지'를 확인하며 코드를 작성하게 된다.

### 1.4 파이썬에서 매개변수 타입을 지정하지 않는 이유

파이썬이 **동적 타입(Dynamic Typing) 언어**이기 때문이다.

C언어는 컴파일할 때 타입을 미리 엄격하게 검사하는 반면, 파이썬은 코드가 실행될 때(런타임) 들어오는 값에 따라 타입을 자동으로 판별한다. 그래서 함수를 정의할 때 `int`나 `string` 같은 타입을 고정하지 않고 유연하게 쓸 수 있다.

**⚠️ 헷갈리기 쉬운 점**

- **`print()`의 반환값**: `print()`는 화면에 출력을 해주기 때문에 아웃풋(반환값)이 있는 것처럼 느껴지지만, 실제 함수의 반환값(Return value)은 `None`이다. '화면에 보여주는 것'과 '값을 돌려주는 것(`return`)'은 다르다.
- **동적 타입의 주의점**: 파이썬은 타입을 명시하지 않아 개발이 유연하고 빠르지만, 프로젝트가 커지면 잘못된 타입의 값이 들어가 런타임 에러가 발생하기 쉽다. 이를 방지하기 위해 실무에서는 `def add(a: int, b: int) -> int:`와 같은 타입 힌트(Type Hint)를 자주 사용한다.

## 2. 삼항연산자와 가독성 좋은 코드 작성법

### 2.1 삼항연산자 (Ternary Operator)

삼항연산자는 `if-else` 조건문을 **한 줄로 간결하게 줄여 쓰는 문법**이다.

- **파이썬 문법**: `참일_때_값 if 조건 else 거짓일_때_값`
- **타 언어와의 차이**: 다른 언어(`조건 ? 참 : 거짓`)와 순서가 다르므로 주의해야 한다.
- **사용 목적**: 리스트 컴프리헨션 안에서 조건부 값을 처리하거나, 변수에 조건별로 간단한 값을 대입할 때 코드 길이를 줄이기 위해 사용한다.

### 2.2 Truthy / Falsy를 활용한 조건식 단축

짝수·홀수를 판별할 때 `return '홀' if n % 2 else '짝'`과 같이 작성할 수 있다.

- **동작 원리**: `n % 2`의 결과는 홀수일 때 `1`, 짝수일 때 `0`이 된다. 파이썬에서는 `1`을 `True`(Truthy), `0`을 `False`(Falsy)로 평가하므로 조건문이 정상 동작한다.
- **실무 팁**: 숫자의 `0`/`1`이나 리스트의 비어있음 여부를 조건문에 바로 활용해 코드를 단순화할 수 있다. 다만 가독성을 위해 `if n % 2 != 0`처럼 명시적으로 작성하는 경우도 많다.

### 2.3 변수명과 저장되는 값의 의미적 일치

할인율 계산 시 `discount_rate`라는 변수에 `0.85`가 아닌 `0.15`(15% 할인)를 저장하는 것이 올바른 코드 작성법이다.

```python
# 할인율 설정 (15% 할인 = 0.15)
discount_rate = 0.15

# 물건 총 합계 계산 후 할인 적용
total = total * (1 - discount_rate)
```

- **이유**: `discount_rate`는 '할인율'을 뜻하므로 `0.15`를 저장해야 `(1 - discount_rate)` 계산을 통해 최종 지불 비율인 `0.85`가 구해진다.
- **실무 팁**: 변수명(`discount_rate`)과 실제 저장되는 값(`0.15`)의 의미가 일치해야 타인이 코드를 읽을 때 혼란이 없고 수식 버그를 방지할 수 있다.

**⚠️ 헷갈리기 쉬운 점**

- **삼항연산자의 과도한 사용**: 조건문이 복잡한데 삼항연산자로 한 줄에 구겨 넣으면 오히려 가독성이 크게 떨어진다. 간단한 값 대입에만 사용하는 것이 좋다.
- **Truthy/Falsy의 암묵적 평가**: `n % 2`처럼 `0`과 `1`을 `False`/`True`로 바로 쓰는 방식은 코드가 짧아지지만, 협업 시 조건이 한눈에 들어오지 않을 수 있으므로 팀의 컨벤션을 따르는 것이 좋다.

## 3. 조건별 분기 처리: match-case와 딕셔너리 매핑

### 3.1 파이썬의 조건 분기 방식

파이썬 3.10 버전부터는 다른 언어의 `switch-case`문과 유사한 **`match-case` (패턴 매칭)** 문법이 새로 도입되었다. 백엔드 API에서 사용자 권한(admin, user, guest)별 처리나 데이터 구조에 따른 분기를 만들 때 활용할 수 있다.

그러나 단순한 값 매핑 상황에서는 `match-case`나 `if-elif`보다 딕셔너리(Dictionary Mapping)를 활용하는 것이 코드를 훨씬 간결하게 만든다.

### 3.2 딕셔너리 매핑 (Dictionary Mapping)

`if-elif` 조건문을 길게 늘어놓는 대신, 딕셔너리의 Key-Value 구조를 활용해 분기 처리를 구현하는 방식이다.

```python
# 권한별 이동할 페이지 매핑
actions = {
    'admin': '관리자 페이지로 이동',
    'user': '메인 페이지로 이동',
    'guest': '로그인 페이지로 이동'
}

# user_role 값에 따라 문자열을 가져옴 (키가 없으면 기본값 반환)
result = actions.get(user_role, '로그인 페이지로 이동')
```

- **작동 방식**: `user_role`이 `'admin'`이면 `'관리자 페이지로 이동'` 문자열이 `result`에 담긴다.
- **함수 매핑**: 문자열뿐만 아니라 실행할 함수 자체를 딕셔너리의 Value로 저장한 뒤 `actions[user_role]()` 형태로 실행하는 방식으로도 자주 쓰인다.

### 3.3 `.get()` 메서드와 디폴트값

딕셔너리의 `.get(key, default)` 메서드는 첫 번째 인수로 전달받은 Key를 찾고, 해당 Key가 존재하지 않을 경우 두 번째 인수로 전달받은 디폴트값(기본값)을 반환한다.

- **안전장치 역할**: 일반적인 딕셔너리 조회 방식(`actions['hacker']`)은 존재하지 않는 키에 접근 시 `KeyError`가 발생하며 프로그램이 종료된다. 반면 `.get()`을 쓰면 에러 대신 안전하게 기본값을 돌려받을 수 있다.
- **실무 활용**: 백엔드 API 개발이나 사용자 입력 처리 시, 예외 상황으로 인해 서버가 멈추는 것을 방지하는 필수 안전장치로 사용된다.

**⚠️ 헷갈리기 쉬운 점**

- **`.get()` 사용 시 인수 순서**: `.get(찾을_키, 없으면_돌려줄_기본값)` 순서로 작성해야 한다. 두 번째 인수를 생략하면 키가 없을 때 `None`을 반환한다.

## 4. 모듈, 패키지, 라이브러리, 프레임워크와 제어의 역전(IoC)

### 4.1 코드의 구조적 단위 (모듈 → 패키지 → 라이브러리)

파이썬 코드를 **파일 시스템상에서 어떻게 묶어서 관리하는가**에 따른 규모별 구분이다.

- **모듈 (Module)**: 변수, 함수, 클래스를 담고 있는 **단일 파이썬 파일(`.py`)**
- **패키지 (Package)**: 여러 모듈(`.py` 파일)을 폴더 단위로 묶어놓은 **디렉터리 구조**
- **라이브러리 (Library)**: 특정 목적(예: HTTP 통신, 데이터 분석 등)을 해결하기 위해 여러 모듈과 패키지를 하나로 묶어 놓은 **재사용 가능한 도구 모음집**

### 4.2 라이브러리 vs 프레임워크 (핵심 차이: IoC)

단순한 도구의 '양'이나 파일 크기의 차이가 아니라, "프로그램의 메인 실행 흐름(주도권)을 누가 쥐고 있느냐"의 차이로 구분한다.

**① 라이브러리 (Library)**

- **주도권**: **개발자**
- **작동 방식**: 개발자가 프로그램 전체의 시작과 끝(메인 흐름)을 짜고, 작업 도중 필요한 시점에 라이브러리의 함수를 **직접 호출**하여 사용한다.

**② 프레임워크 (Framework)**

- **주도권**: **프레임워크**
- **작동 방식**: 서버 구동, 이벤트 루프, 요청 대기 등 **메인 구동 엔진은 이미 프레임워크 코드로 완성되어 실행 중**이다. 개발자는 프레임워크 규격에 맞춰 실행시킬 로직만 등록해 두며, 특정 조건(요청)이 발생하면 프레임워크가 개발자의 코드를 역으로 호출한다. 이를 **제어의 역전(Inversion of Control, IoC)**이라고 한다.

> ➕ **더 알아두기**
> 8월 3일에 배운 라이브러리·프레임워크 비유("공구 vs 밀키트/공장 라인")가 오늘 IoC라는 정식 이름을 얻었다. 그때는 "규칙에 맞게 부품을 끼워 넣는다"는 결과만 봤다면, 오늘은 **왜 그렇게 되는지**를 배운 것이다 — 프로그램의 시작 버튼을 누가 쥐고 있느냐가 기준이다.
> 이 개념은 이 저장소에서 이미 두 번 실제로 등장했다. n8n의 각 노드는 라이브러리처럼 내가 순서를 짜서 호출하는 게 아니라, **트리거가 울리면 n8n 엔진이 내 노드를 호출**하는 구조라 사실상 프레임워크형 제어다. 그리고 FastAPI로 `@app.get("/hello")`를 등록해두면, 요청이 올 때 FastAPI가 그 함수를 대신 호출해주는 것도 똑같은 IoC다.

### 4.3 코드 패턴 비교

**라이브러리 패턴 (`requests`)** — 내가 메인 흐름을 다 짜고, 필요한 시점에 직접 호출한다.

```python
import requests

# 내가 직접 메인 흐름을 시작하고, requests.get() 함수를 직접 호출
response = requests.get('https://api.github.com')
print(response.json())
```

**프레임워크 패턴 (`FastAPI`)** — 나는 특정 조건에 동작할 함수를 등록만 하고, 실행은 프레임워크 엔진이 맡는다.

```python
from fastapi import FastAPI

app = FastAPI()

# 내가 직접 say_hello()를 호출하는 코드는 없음!
# 프레임워크 규칙(@app.get)에 맞춰 함수를 등록해둘 뿐임
@app.get("/hello")
def say_hello():
    return {"message": "안녕하세요!"}
```

### 4.4 한눈에 보는 비교

| 구분 | 라이브러리 (Library) | 프레임워크 (Framework) |
|---|---|---|
| 개념 | 필요할 때 가져다 쓰는 도구 모음 | 이미 구동 중인 완성된 프로그램 구조(틀) |
| 메인 주도권 | 개발자 | 프레임워크 엔진 |
| 호출 관계 | 개발자 코드 → 라이브러리 함수 직접 호출 | 프레임워크 엔진 → 개발자 코드 역호출 (IoC) |
| 개발 방식 | 내 코드 안에 라이브러리를 부품으로 추가 | 프레임워크가 비워둔 규격(빈칸)에 내 코드를 작성 |

1. 함수를 쓰는 가장 큰 이유는 무엇인가? 프로젝트가 커질수록 왜 더 중요해지는가?
2. `print()`가 화면에 뭔가를 보여주는데도 반환값이 `None`인 이유는? "출력"과 "반환"의 차이는?

4. 파이썬이 함수 매개변수에 타입을 지정하지 않아도 되는 이유는? 그 대신 실무에서 쓰는 안전장치는?
